# Lint

`bun run lint` is the lint gate every PR runs (AD-28.1): CI's required `ci.yml#check` job runs it, so a lint failure fails the PR (Stories 6.1, 6.2, 6.3; NFR-3, AD-6, AD-16.4). It is two commands, chained:

```sh
bun --bun oxlint --type-aware && bun run lint:disables
```

## oxlint (`.oxlintrc.json`)

oxlint 1.88.0 with oxlint-tsgolint 7.0.2004 (root `devDependencies`), run type-aware. The root `.oxlintrc.json` enables the `correctness` category as errors, and these rules at the top level, so they apply to every linted path: `packages/*/src`, `packages/*/tests`, `skeleton/` and the compiled-view snapshots (which land under `packages/view/tests/`, Story 49.1):

| Rule | Setting | Why |
| --- | --- | --- |
| `typescript/no-floating-promises` | `["error", {"checkThenables": true}]` | an unawaited Promise, or an unawaited thenable Builder, Relation or `PendingRequest` (AD-6) whose terminal never runs |
| `typescript/await-thenable` | `"error"` | `await` on a value that is not a Promise or thenable |
| `typescript/no-misused-promises` | `["error", {"checksVoidReturn": true, "checksConditionals": true}]` | an async callback passed where a `void` return is expected, whose rejection nobody sees; a Promise used as a condition, which is always truthy (`checksConditionals`: ESC-6.1-1, Story 6.6) |
| `unicorn/no-thenable` | `"off"` | AD-6 makes Builders, Relations and `PendingRequest` thenable by design |

One more rule is on for framework packages and Ported Tests only, in the config's one `overrides` entry, `{ "files": ["packages/**"], "rules": { "typescript/return-await": ["error", "always"] } }` (Retro 6 item 11; Maintainer ruling [item 6](../../decisions/MAINT-2026-10-19-epic-6-items.md)):

| Rule | Setting | Scope | Why |
| --- | --- | --- | --- |
| `typescript/return-await` | `["error", "always"]` | `packages/**` (override globs resolve against the config's directory, so not `skeleton/`, `installer/`, `tools/` or `conformance/`; `installer/` is not a framework package) | an `async` function that returns a Promise or thenable without `await`. Type-aware, so it sees `async find() { return this.query(); }` where `query()` returns a thenable `Builder`, which the syntactic `xaravel/no-async-thenable-return` cannot (finding L1). It is stricter than spine:183 (every returned Promise is awaited, not only thenables); that is accepted, since `return await` keeps async stack traces and makes a thenable's terminal explicit |

The Skeleton keeps only `xaravel/no-async-thenable-return`, so App Developers do not inherit a style rule (as do `installer/`, `tools/` and `conformance/`, which are outside `packages/`); a Skeleton `async` function returning a thenable from a call therefore still passes lint (see the limits below). `checkThenables` fires only for a `then` typed as `PromiseLike`. The type-aware rules (`no-floating-promises`, `await-thenable`, `return-await`) judge a thenable by its `then` signature, not by name, so they see a Pipeline as a thenable (ESC-10.2-2) only once Story 10.2 adds the contract's `PromiseLike` `then(onFulfilled, onRejected)` overload (that ruling's contract half); Epic 10 retro item 4 covers only the name list that `xaravel/no-async-thenable-return` and `bun run async-surface` read. The config has no other `overrides`, and no `ignorePatterns` entry may match `packages/` or `skeleton/` files. `.oxlintrc.json` is plain JSON (no comments): tests read it with `JSON.parse`, so the rationale lives here.

The committed fixtures in `tools/lint-rules/fixtures/async-safety/` prove the rules: `floating-thenable.ts`, `await-plain.ts`, `misused-void-callback.ts` and `misused-conditional.ts` (a Promise as an `if` condition, Story 6.6; it carries a `@ts-expect-error` for TS2801, which tsc also reports, so the fixtures typecheck) each fail one rule, and `passing.ts` holds all four patterns done right (an awaited Promise as the condition). The root config ignores the fixtures directory so `bun run lint` stays green; XT-conformance-129 and XT-conformance-130 copy the first three fixtures into temp roots and lint them with the real config, from the repository root (oxlint finds tsgolint from the cwd), with `--format unix`. XT-conformance-254 lints `misused-conditional.ts` the same way (exactly `no-misused-promises`), shows that `checksConditionals: false` lets it pass, and that `lint:disables` then fails with `sets no-misused-promises without checksConditionals: true`. `return-call-result.ts` is a `Repository` whose `async find(): Promise<readonly string[]>` and unannotated `async findAll()` return `this.query()`, a sync `Builder`, and whose `async first()` returns `await this.query()`, the fixed form; XT-conformance-255 lints it with a temp copy of the real config (its `jsPlugins` made absolute, so the override's `packages/**` resolves against the temp root) at `packages/demo/src`, `packages/demo/tests/ported` and `skeleton/app`: exactly two `return-await` at each of the first two (the `find()` and `findAll()` lines; `first()` is clean), nothing in the Skeleton.

## The `xaravel` plugin (`tools/lint-rules/plugin.ts`)

Story 6.2 adds an oxlint JS plugin, loaded by the root config's `"jsPlugins": ["./tools/lint-rules/plugin.ts"]`, with six rules for the spine's identity, value and test-hygiene conventions. Each is `"error"` at the top level of `.oxlintrc.json` and a spine rule (`SPINE_RULES`), so no directive or config may switch it off. The rules need no type information. Each message names the AD it enforces.

| Rule | Scope | Reports | Why |
| --- | --- | --- | --- |
| `xaravel/no-identity-constructor-name` | every linted file except the grader's locations (`packages/assert/`, `packages/mockery/`, `conformance/`, `tools/`), which cannot call `fqcn()` under AD-15's grader isolation, so their class-name reads are display only (ruling [decisions/ESC-6.2-1.md](../../decisions/ESC-6.2-1.md)) | a read of `<expr>.constructor.name`: dot, optional (`?.`) or computed string access, and `const { name } = <expr>.constructor` (also in an assignment). A bare identifier called `constructor` is not matched | identity is `fqcn()` (AD-10) |
| `xaravel/no-framework-json-stringify` | `packages/<p>/src/` where `<p>` is not a grader package (`assert`, `mockery`) | any reference to `JSON.stringify`, `JSON["stringify"]` or `globalThis.JSON.stringify`, called, aliased or destructured (`const { stringify } = JSON`) | encode with `jsonEncode` / `phpSerialize` (AD-23). "On a framework value" needs types the rule does not have, so it bans every reference; `jsonEncode` covers any legitimate need |
| `xaravel/no-ported-bun-expect` | every file under `packages/<p>/` (src, tests and support alike, the grader packages `assert` and `mockery` included on purpose: Ported Tests import `@xaravel/assert`, so it must not re-export Bun's `expect`) for exports and test-globals references; files under a `tests/ported/` directory for the rest. A path is anchored like the grader exemption, so `conformance/…/packages/demo/` is not a package file | in any package file: every export of `bun:test`'s `expect` or namespace. That is `export { expect } from "bun:test"` (any alias), `export *` / `export * as` of `bun:test`, `export import b = require("bun:test")`, and an export (`export { x }`, `export { x as y }`, `export default x`, `export = x`, `export const c = x`, or `export const { expect } = x`) of: a value-imported `expect` (any alias), a `bun:test` namespace (`import * as`, `import b = require`), a `require("bun:test")` / `<obj>.require("bun:test")` / `import("bun:test")` value (awaited or not), `.expect` / `["expect"]` of one of those, a global `expect` (`globalThis.expect`, `global.expect`, `self.expect`, `window.expect`, or an `expect` bound nowhere in the file), through `as` / `satisfies` / `!` / parentheses; imports are hoisted, so order does not matter. Also a `/// <reference types="…test-globals…" />` or `/// <reference path="…test-globals…" />` comment, since a support `.d.ts` would leak the globals into Ported Tests. In a Ported Test also: a value import of `expect` (any alias), a namespace import or `import b = require` of `bun:test`, `import("bun:test")`, `require("bun:test")` and `<obj>.require("bun:test")` (`import.meta.require`), a global `expect` (bare and bound nowhere in the file, at any depth, or read from `globalThis`, `global`, `self` or `window` by member or destructuring), and an ambient declaration of `expect` (`declare const`, `declare function`, or inside `declare global` / `declare module` / `declare namespace`), which would make Bun's runtime global look local. Type-only imports and exports are not matched, and a plain `import { expect } from "bun:test"` in a non-ported package file (a Xaravel Test) is clean. The rule reads the scope manager (`sourceCode.getScope`), and throws naming itself if oxlint gives none | Ported Tests use only `portedTest(...)` and `@xaravel/assert` (AD-15) |
| `xaravel/no-type-import-injection` | every linted file | an identifier bound by `import type {X}` or `import {type X}` (any module) referenced in value position inside the arguments of an `inject(...)` call or `@inject(...)` decorator (callee `inject` or `<obj>.inject`). Type arguments, annotations and non-computed keys are not references | a contract injected must be imported as a value (AD-1); tsc reports the same misuse as TS1361 |
| `xaravel/no-model-private` | `packages/database/src/Eloquent/Model.ts` and `packages/database/src/Eloquent/Concerns/**` | every `#private` name: field, method, accessor, `this.#x`, `#x in o` | the `Model` Proxy cannot reach `#private`; use a Symbol slot (AD-7) |
| `xaravel/no-package-default-export` | `packages/<p>/src/` and `installer/src/` | `export default`, `export { x as default }`, `export { default } from`, `export * as default from` | named exports only (AD-3). Skeleton app convention files (`config/*.ts`, migrations) are outside the scope, so they may default-export |

A path scope tests the file's path relative to the cwd when it is inside it, else its absolute path, matched by segment (`(^|/)packages/[^/]+/src/`), so the rules hold on the real tree and on temp roots. The grader exemption is anchored: a cwd-relative path must start with a grader location, and an absolute path is judged from its first root-level segment (`packages/<p>/`, `conformance/`, `tools/`, `skeleton/`, `installer/`), so a nested `packages/demo/src/tools/` is not exempt. The grader packages come from one list, `GRADER_PACKAGES` in `tools/lint-rules/plugin.ts`, from which the exemption's location pattern is built; the same list scopes `no-framework-json-stringify` (`isFrameworkSource`). XT-conformance-132 checks the list and both scopes against the `kind: "grader"` rows of `tools/scaffold/packages.jsonl`, and the registration scan test (XT-conformance-141) checks the list too, so a grader package is added or removed in `GRADER_PACKAGES` and `packages.jsonl` together. The root config must keep `./tools/lint-rules/plugin.ts` in `jsPlugins` (a string or `{ "specifier": … }` entry); `lint:disables` fails a root config that drops or repoints it. Rule names are compared by their last `/` segment, so a custom rule's name must not collide with an oxlint built-in (hence `no-package-default-export`, not `no-default-export`).

The committed fixtures in `tools/lint-rules/fixtures/identity-values/` prove the rules: `constructor-name.ts`, `json-stringify.ts`, `ported-expect.ts`, `type-import-injection.ts`, `model-private.ts` and `default-export.ts` each fail one rule at its scoped path; `passing.ts`, `passing-expect.ts` and `passing-ported.ts` hold the near-misses (named exports, a `jsonEncode`-style call, `fqcn(x)`, a value-imported token in `inject`, a `MODEL_STATE` Symbol slot, a parameter named `constructor`, `expect` outside `tests/ported/`, a type-only `expect` import); `support.ts` stands in for `inject`, `fqcn`, `jsonEncode` and a contract token. `type-import-injection.ts` carries a `@ts-expect-error` for TS1361 so the fixtures typecheck. XT-conformance-132 copies them into temp roots at each rule's placements, adds inline edge cases, and lints them with the real config from the repository root with `--format unix`.

### Async signatures, frame state and declarations (Story 6.3)

Story 6.3 adds seven more rules to the plugin, each `"error"` at the top level and a spine rule, each scoped to every linted file. Like the six above they need no type information (oxlint JS plugins get none), so the AD-6 rules decide from declared types and the shape of returned expressions: a `T | Promise<T>` hidden behind an alias (`MaybePromise<T>`) is invisible to them, and Story 6.4's `.d.ts` walk is the backstop for emitted signatures.

| Rule | Reports | Why |
| --- | --- | --- |
| `xaravel/no-maybe-promise-return` | a public signature whose declared return type is a union with at least one `Promise<…>` / `PromiseLike<…>` member and at least one other member (nested unions and parentheses flattened). Public: a class method, getter or abstract method that is not `private`, `protected` or `#private`; an interface or type-literal method signature, or a property signature whose type is a function type; an exported function declaration, overload or `declare function` (exported directly or by a later `export { f }`); a public class field, or an exported `const`, holding a function or arrow literal with a declared return type. An overload implementation (a body after bodyless overloads of the same name) is not public. Callback parameter types (a method signature inside a function type or parameter) are never checked | a method that is async on any path is async on every path; never return `T \| Promise<T>` (AD-6) |
| `xaravel/no-async-thenable-return` | in an `async` function, method or arrow: a declared `Promise<X>` where X (or a member of its union) names a thenable; a `return` (or arrow expression body) that is `new X(…)`, `<expr> as X`, or an identifier whose same-function `const` / `let` is annotated `X` or initialised `new X(…)`. An `await`ed thenable is fine. The thenables are `THENABLE_TYPES`, the one list `@xaravel/contracts/async` exports, which `tools/lint-rules/thenables.ts` re-exports as the same array (the Query and Eloquent `Builder`, the Relation classes, `PendingRequest`, `PendingDispatch`, `PendingClosureDispatch`, `PendingChain`, `PendingBatch`, `PendingBroadcast`, `PendingCommand`, `PendingTestResponse`, and the Pipeline contract and class, ESC-10.2-2), matched by qualified name, never by short name: a name `X` (or `ns.X` through `import * as ns`) counts when its import, followed by `registeredFqcn` through `export {} from`, imported-then-exported bindings and `export *` to the module that calls `registerClass('<FQCN>', X)` or declares the contract token `const X = contract("<FQCN>", …)` (with `contract` imported by name; a `registerClass` of the same local wins), or, when reached from another module (an import, a re-export or `export *`), to a structural type in `packages/contracts/src/structural/<Name>.ts` that exports `<Name>` under that name, registers nothing for it, and whose first line names the class as `// <FQCN>,…` or `// <FQCN> …` (ESC-10.3-2), or a same-file `registerClass` or token, yields a listed FQCN (compared without a leading `\`, case-insensitively; the message names it), the resolution [async-surface.md](async-surface.md#how-it-works) describes. Also any class in the same file that `implements PromiseLike` / `Thenable` or declares a `then` method | an async function returning a thenable resolves to its terminal's result, running it implicitly (AD-6) |
| `xaravel/no-singleton-field-write` | in a class whose file has `registerClass('<FQCN>', X)` (callee `registerClass` or `<obj>.registerClass`) with the FQCN in `singletons.json` `classes`: a `this.<field>` (or `this.#field`) assignment, compound assignment, destructuring target, `++` / `--` or `delete` anywhere but the constructor body proper and field initialisers. A write in a function or arrow nested in the constructor runs after construction, so it is reported. A boot-only property of the class is left to the next rule | a singleton's fields are shared by every request; per-request state goes in Scope Frame slots (AD-5) |
| `xaravel/no-boot-only-write` | in a class whose file registers an FQCN with entries in `singletons.json` `bootOnly`: a write to a listed property (`this.p` assignment, update or `delete`; an assignment to `this.p[…]` or `this.p.x`; a `push`, `unshift`, `splice`, `pop`, `shift`, `set`, `add`, `delete` or `clear` call on `this.p`) outside the constructor and the property's `writers` (compared case-insensitively), or inside a function nested in a writer | boot-only state is written only on the register/boot path and sealed after boot (AD-5) |
| `xaravel/no-arrow-test-body` | in a file that calls the bare identifier `uses(…)`: an arrow function passed to `test`, `it`, `beforeEach`, `afterEach`, `beforeAll` or `afterAll`, or their `.only` / `.skip` / `.todo` / `.failing` / `.concurrent` forms and the curried `.each(…)(…)` / `.if(…)(…)` / `.skipIf(…)(…)` / `.todoIf(…)(…)` forms | a Pest-style test bound to a test case needs a `function` body so `this` is the case (AD-25) |
| `xaravel/no-inject-param-mismatch` | `inject({…})` as a class decorator (the class's own constructor parameters; a class with no constructor and no `extends` has none; one that `extends` without its own constructor is skipped), as a method decorator (that method's parameters), or `inject(map, fn)` with a function or arrow literal: the key list must equal the parameter names, in order. Names come from identifiers, defaulted parameters, TS parameter properties and rest elements; a TS `this` parameter is ignored; a destructured parameter, a spread or a non-static key is a mismatch, and so is a map that is not an object literal (`@inject(DEPS)`), whose keys cannot be checked. The message lists both | key order is parameter order and key names are parameter names (AD-4) |
| `xaravel/no-dynamic-column-default` | in a class extending `Model`, `Pivot`, `MorphPivot`, `Authenticatable` (or `<ns>.<one>`) or `mixin(<one of them>, …)`: a non-static, non-`declare` field initialiser that is not a constant expression, except the Model config fields (`table`, `connection`, `primaryKey`, `keyType`, `incrementing`, `timestamps`, `attributes`, `fillable`, `guarded`, `casts`, `hidden`, `visible`, `appends`, `with`, `withCount`, `perPage`, `dateFormat`, `touches`). Constant: a literal other than a regex (which builds a fresh object), `null`, a template literal with no substitutions, unary `-` / `+` / `!` on a constant, an array or object literal of constants with static keys, or a constant wrapped in `as` / `satisfies` / `!` / parentheses | a column with a default is an initialised field holding the cast value, harvested as the model's attribute default, and the default must be a constant expression (AD-7) |

Limits, since the rules see one file and no types:

- `no-ported-bun-expect` follows only the direct forms listed above; what it does not see includes, among others: an `expect` passed through an object, function, array or reassignment (`export const api = { expect }`, `let x = e; export { x }`); `Reflect.get(globalThis, "expect")` or an aliased global object (`const g = globalThis; g.expect`); exports nested inside a `namespace`; a tsconfig `types: ["bun-types/test-globals"]` entry (oxlint never reads tsconfig, though the global-`expect` check still catches the runtime use in a Ported Test); and a re-export from a file outside `packages/<p>/` (`conformance/`, `tools/`, a root-level helper).
- `no-singleton-field-write` covers direct `this.<field>` writes only. Element writes (`this.cache[k] = v`, `delete this.cache[k]`) and mutating calls (`this.items.push(x)`) are not reported, except on a boot-only property, where `no-boot-only-write` covers them.
- Both AD-5 rules see only the body of the class the file registers. They do not see base classes or mixins declared in other files, or static writes spelled `ClassName.prop`. A write under a nested non-arrow function (a function expression or declaration, or an object-literal method) is not matched, because its `this` is not the instance. A `static { … }` block counts as construction time.
- `no-async-thenable-return` resolves a thenable only through what the file writes: a local class with a thenable's short name that is not registered under a listed FQCN, `export default class X` / `export default X` (`export { X as default }` is followed), `export * as ns`, a type alias and a relative specifier with no `.ts` file behind it are not thenables to it (Retro 6 item 12; the resolution limits in [async-surface.md](async-surface.md#limits) apply). Scope is not tracked: a type parameter or inner-scope binding that shadows an imported name resolves through the import. Unlike `bun run async-surface`, it does not resolve `this`: `Promise<this>` in a method of a listed class is not reported. It reads the imported modules from disk, so an unsaved buffer elsewhere is not seen. It does not follow call chains (`return this.query()`). Under `packages/` the type-aware `typescript/return-await` (`always`) catches that case; in the Skeleton nothing does, by the Maintainer's ruling (item 6).
- `no-dynamic-column-default` sees only a direct `Model`, `Pivot`, `MorphPivot` or `Authenticatable` base (or `mixin(…)` of one), not a subclass of one declared elsewhere.

The two singleton rules read `tools/lint-rules/singletons.json`, generated by `bun run scan:singletons` ([scans.md](scans.md)); its `bootOnly` entries carry each boot-only property's writers, the scan's register/boot path. The plugin uses the file under the linted file's repository root (the cwd for a cwd-relative path; for an absolute path, the directory before its first root-level segment) when that root has one, else the one beside `plugin.ts`, so a temp root can carry its own. A file that does not parse, or lacks the `classes` and `bootOnly` arrays, fails the run with an error naming its path; it never silently turns the rules off. Never edit the file by hand: regenerate it. The `no-boot-only-write` message lists the writers lower-cased, as the scan records them, and says they are compared case-insensitively.

The committed fixtures in `tools/lint-rules/fixtures/signatures-state/` prove the rules: `maybe-promise.ts`, `async-thenable.ts`, `singleton-write.ts`, `boot-only-write.ts`, `arrow-test-body.ts`, `inject-mismatch.ts` and `dynamic-column-default.ts` each fail one rule; `passing.ts` holds the near-misses (overloads, a callback parameter, non-public members, an awaited Builder, a Router writing its fields in the constructor and `groupStack` in `group()` / `updateGroupStack()`, a non-singleton class, matching `inject` keys, constant column defaults and config fields), `passing-tests.ts` arrow tests in a file without `uses()`, and `passing-uses.ts` `function` bodies in one with it; `support.ts` stands in for a thenable `Builder` (registered as `Illuminate\Database\Query\Builder`, so an import of it resolves), `registerClass`, `inject`, contract tokens, `Model` and `uses` / `test`. XT-conformance-133 places them in temp roots, adds inline edge cases (the I/O matrix of the Story included, and an `async` function declared `Promise<Pipeline | null>` that imports a `Pipeline` contract token, Epic 10 retro item 4, and one declared `Promise<PendingDispatch | null>` that imports the structural `PendingDispatch` from a temp `packages/contracts/src/structural/PendingDispatch.ts`, Epic 10 retro item 6) and a temp root with its own `singletons.json`, and lints them with the real config from the repository root with `--format unix`.

## The async surface (`bun run async-surface`)

The rules above see one source file and no types. Story 6.4's `bun run async-surface` (CI's `check` job, after the typecheck) is AD-6's backstop over the emitted `.d.ts`: every Promise-returning public method must carry `@asyncRoot <Contract.method>` or `@asyncRoot callback`, a sync thenable-returning one carries no tag and is recorded on a `thenable` line, and each package's committed `async-surface.json` must match the regenerated one. See [async-surface.md](async-surface.md).

## No disabling (`bun run lint:disables`)

AD-16.4: an `oxlint-disable` of any rule the spine names fails CI.

```sh
bun run lint:disables                                   # the real repository
bun --no-env-file tools/lint-rules/disables.ts --root <dir>
```

It reads only, and checks:

- **Directives.** Every file oxlint lints (`git ls-files -co --exclude-standard` with oxlint's extensions `.ts .tsx .mts .cts .js .jsx .mjs .cjs`, minus the root `ignorePatterns`) is tokenized, so only real `//` and `/* */` comments count, never text inside a string, template literal or regex. A comment starting `oxlint-disable`, `oxlint-disable-line`, `oxlint-disable-next-line` or an `eslint-` spelling is a directive. Its rule list is the comma-separated text up to a ` -- ` description. A rule is compared by its last `/` segment, so `no-floating-promises`, `typescript/no-floating-promises` and `@typescript-eslint/no-floating-promises` are the same rule. A directive naming a spine rule fails; so does one naming no rule, since it disables every rule. In a file under `packages/` (a file directly in it included, since `packages/**` covers it) a directive naming a package rule (`PACKAGE_RULES`: `return-await`) fails too; outside `packages/` it is allowed. Directives for other rules (`no-control-regex`, `typescript/unbound-method`, …) are allowed.
- **Configs.** The root `.oxlintrc.json` and every nested `.oxlintrc.json` / `.oxlintrc.jsonc` must leave each spine rule at `error` with its options. A nested config replaces the root's for its directory unless it `extends` it, so a nested config that omits a spine rule disables it and fails. An `overrides` entry that lowers or weakens a spine rule or a package rule fails, as does a `plugins` list without `typescript`, a config that does not parse, and an `oxlint.config.*` JS config (the check cannot read one).
- **Package rules.** Each `PACKAGE_RULES` entry must be `error` with its `RULE_MODES` mode, the setting's second array element (`return-await`: `["error", "always"]`). In the root config the setting is taken per `PACKAGE_PROBES` path (`packages/demo/src/Demo.ts`, `packages/demo/tests/ported/DemoTest.ts`): the top-level `rules`, then each `overrides` entry whose `files` globs (`Bun.Glob`, relative to the config's directory) match the probe, in order, so dropping the override or a later override that lowers it fails naming the probe. When the probes hold, every protected path under `packages/` (the fixed probes, a `Demo<ext>` per linted extension, and each listed package file) is checked the same way and the first that falls short is named, so an override narrowed to `packages/demo/**` or `packages/**/*.ts` fails too: `.oxlintrc.json:1:1: does not set return-await (a spine rule must be "error") for packages/demo/src/Demo.ts (AD-16)`, or `sets return-await without "always" for …`. A nested config under `packages/` replaces the root's config, overrides included (an `extends` brings in only the root's `rules`; probed with oxlint 1.88.0), so its own effective `rules` must carry each package rule: `packages/demo/.oxlintrc.json: does not set return-await …`.
- **Ignores.** No `ignorePatterns` entry in any config (matched relative to that config's directory), and no line of a root `.eslintignore` (which oxlint honours by default), may exclude a protected path. The protected paths are fixed probes under `packages/*/src`, `packages/*/tests`, `skeleton/` and the compiled-view snapshots, one `packages/demo/src/Demo<ext>` per linted extension, and every listed linted file under `packages/*/src`, `packages/*/tests` and `skeleton/`. The violation names the entry and the first path it excludes.
- **Git excludes.** oxlint skips what git ignores, so no git exclude rule may match a protected path, a build-directory probe (`packages/demo/src/build/Demo.ts`, `packages/demo/src/dist/Demo.ts`, `packages/demo/src/coverage/Demo.ts`: `GITIGNORE_PROBES`) or any listed linted file outside the root `ignorePatterns`, including a tracked, force-added one. Git's own matcher decides (`git check-ignore --no-index -v -z --stdin`), so the root and nested `.gitignore`, `.git/info/exclude` and `core.excludesFile` all count; a negated (`!`) match re-includes the path and passes. The violation is at the ignore file's line, column 1: `.gitignore:1:1: entry "Bad.ts" excludes packages/demo/src/Bad.ts from the spine rules (AD-16)`. A git failure fails the run (`lint disables: check failed: …`). The root `.gitignore` therefore anchors its build output (`/dist/`, `/build/`, `/coverage/` and `/packages/*/dist/`, `/packages/*/build/`, `/packages/*/coverage/`), so a source directory named `build/` under `packages/*/src` is still linted.

Each violation is one stderr line, `<path>:<line>:<col>: <message> (AD-16)`. Exit codes: 0 none (prints `lint disables: ok (<n> files)`), 1 any violation, 2 usage error. XT-conformance-131 covers it.

## Adding a spine rule (Story 6.3)

The spine's rules live in one constant, `SPINE_RULES` in `tools/lint-rules/disables.ts`; a rule that must carry options also gets an entry in `SPINE_RULE_OPTIONS`. A Story adding a custom rule adds it to the `xaravel` plugin, appends its name (the last `/` segment) to `SPINE_RULES` and sets the rule to `error` at the top level of `.oxlintrc.json`. From then on the root config must hold it and no directive may disable it. A rule for framework packages and Ported Tests only goes in `PACKAGE_RULES` instead (with its mode in `RULE_MODES` if it takes one), set in the root config's `packages/**` override. Four tests pin that override exactly, so each changes with it: XT-conformance-129 and XT-conformance-255 (`conformance/tests/xaravel/lint.test.ts`), XT-conformance-132 (`lint-rules.test.ts`) and XT-conformance-133 (`lint-signatures.test.ts`). Story 6.2 did this for its six rules and Story 6.3 for its seven; each also extends `RULE_NAMES` in the plugin (in `plugin.rules` order) and the pins in XT-conformance-131 and XT-conformance-132.
