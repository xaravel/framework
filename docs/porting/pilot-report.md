# `PORTING.md` pilot report (Story 8.7)

FR-8.2 requires `PORTING.md` to be piloted on real Support and Collections tests and revised from the evidence before Phase 1 starts. This report records the pilot under the ESC-8.7-1 ruling: a seeded, stratified sample, translated by fresh-context agents from `PORTING.md` alone, then type-checked against declaration-only `.d.ts` files, measured against a static assertion floor, and reviewed by the in-loop Fidelity Review (ESC-8.5-1). The translations, the declarations and the pilot tooling live only on the unmerged `pilot/porting` branch; Epics 14 and 18 port these files for real. XT-conformance-166 and XT-conformance-167 (`conformance/tests/xaravel/porting-pilot.test.ts`) check this report against the Inventory, the seed and `PORTING.md`.

Test IDs in the `## Rules hit` and `## Ambiguities` tables omit the `Illuminate\Tests\Support\` namespace.

Every member is typed `any`; nothing is implemented, and no test runs against them.
- Floor: 64 Test IDs, 34 `met`, 30 `approximate`, 0 `adapted`, 0 `short` (`bun pilot/floor.ts`). `pilot/floor.ts` counts, in each `portedTest` body, `this.assertX(...)` and `Assert.assertX(...)` as kind `assertX`, `this.expectExceptionObject(...)` as 3 `assertThat` (class, message and code, as PHPUnit records them) and every other `this.expectException*(...)` as 1 `assertThat`, and compares each kind with the Inventory row's `assertions`.

The first review then rejected four points, fixed in `fe58b87`: list-keyed expected arrays became JS Arrays (DIV-9.2); `isset` on an `all()` result reads `phpArrayEntries`; every converted PCRE pattern carries `// adapted:DIV-10.1`; and `pilot/evidence.ts` writes `pilot/evidence.md`, which gives the reviewers the Upstream data providers and the `conformance/oracle/nondeterminism.jsonl` line for `SupportStrTest::testItCanFreezeUuidsInAClosure`, whose committed request has no fixture by design.
- Not a `PORTING.md` gap, left for the Maintainer: the review prompt (`tools/fidelity-review`) carries a provider-row test's method lines but not its data provider, and it reports a nondeterministic request's absent fixture as an unavailable error fixture (F-6).
