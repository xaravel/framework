# OQ-12: security releases may bump the Pin mid-Phase

A security-relevant Upstream release may trigger an out-of-cycle pin bump during a Phase. A release is security-relevant when its release notes, or a GitHub Security Advisory for `laravel/framework` or a package the Oracle locks, name a security fix.

The bump runs the normal pin-bump flow with nothing skipped: `bun run pin:bump <tag>`, the regenerated locks, Oracle image, Inventory and fixtures, the diff-mode Expectations update, and the Maintainer's review of the Infrastructure PR. The only change is that `pin:bump`'s freeze-point refusal (it refuses while an epic is `in-progress`) gets a Maintainer-only override that names the advisory and is recorded in the pin-bump PR. Only the Maintainer decides that a release is security-relevant and authorises the override, so it cannot be used to pull in ordinary minors, which still wait for a Phase boundary.

The override is built by Epic 8 action item 3. Until it exists, an urgent bump needs its own Escalation.
