# ESC-4.7-1: approved, with these owners and one amendment

The Maintainer approved this in the Maintainer's session on 2026-10-19. With this ruling, Story 4.7's acceptance criteria are met.

- **(1)** The kind-less count is adopted as proposed. `addToAssertionCount(n)` and mock verification count toward FR-113's zero-assertion rule and `expectNotToPerformAssertions`, never toward the report's `assertions`. The report keeps its four keys, and Story 5.3 reads it unchanged.
- **(2)** The DIV-6 clause is adopted, amended to use the signature lookup of ESC-4.8-1 item 1. When the double's target has a surface row for the method, PHPUnit's test doubles take the declared return type, parameter names and defaults from that row: an unconfigured call returns PHPUnit's generated value for the declared type, `Invocation::toString` carries its `: <type>` suffix, an omitted argument is padded with its declared default, and `willReturnMap` rows are normalized with the declared defaults. Story 9.11 (component `assert`) makes this change in `@xaravel/assert`. When there is no row, as for a test-local class, the clause applies as proposed: an unconfigured call returns null, parameter names come from the JS source, and null is every default. Story 9.11 also decides whether `willReturn` is type-checked against the row. It is recorded in Story 8.1's DIV records as "DIV-6 php-only: PHP run-time types and reflection in test doubles", covering both the targets without a row and the parts no row can supply: a double made without the constructor runs no JS field initializer, a real method of a partial mock that touches a `#private` field throws, a built-in subclass's double lacks its internal slots, "final or static" never applies, and every JS error reaching the invocation handler is treated as PHP's `\Exception`. Ported Tests that rely on a generated return value for a target without a row configure it, as an `adapted:DIV-6` change.
- **(3)** PHPUnit's test-double notices and deprecations (the no-expectations notice, the `any()` deprecation, `with()` without `expects()`) are an outcome-neutral, message-only difference, as in ESC-4.4-2 item 3. It is recorded as a clause in Story 8.1's DIV records.
- **(4)** The `globalThis[Symbol.for('xaravel.mockery.mock')]` hook is already gone: Story 4.8 removed it, and `packages/mockery/tests/xaravel/mockery.test.ts` now asserts that it is not installed. `epics.md` Story 4.4's criterion "it delegates to `@xaravel/mockery`" now reads "it returns a PHPUnit test double (`MockObject`), as PHPUnit does", which matches `epics.md:114` and ESC-4.4-2 item 6.
- **(5)** Story 10.1's contract tokens carry their method names at `Symbol.for('xaravel.contract.methods')` (ESC-4.5-1 item 3) and, for test doubles, each method's parameter names, as proposed. The surface records the methods of every Upstream interface, so the token generator can read both from it. A bare symbol target still has no method list.

Rationale: the kind-less count is how PHPUnit counts, and without it the 425 Inventory entries that pass with `"assertions":{}` would fail the zero-assertion rule. The amendment to (2) applies ESC-4.8-1's ruling to both kinds of test double: the committed surface carries the declared signature for every framework class and interface, so the null default is needed only where no row exists, and fewer Ported Tests need an `adapted:DIV-6` change. What remains under DIV-6 comes from JS having no PHP property defaults, private slots or `\Error`/`\Exception` split at run time. The notices change no outcome. No expected value of a Laravel test is weakened.
