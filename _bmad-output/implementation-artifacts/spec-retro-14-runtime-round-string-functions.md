## Intent

**Scope:** `packages/runtime/**` only, under amendment 2026-10-22 of `decisions/MAINT-2026-10-16-unattended-orchestrator.md`. This spec and sprint status may change too.

**Approach:** `@xaravel/runtime/php` and the package root export, under their PHP names, ports of PHP 8.5.11 (`ext/standard/math.c` `PHP_FUNCTION(round)`, `_php_math_round`, `php_round_helper`, `php_math_round_mode_from_enum`; `ext/standard/array.c` `reset` / `end`; `ext/standard/string.c` `strtoupper`, `php_trim_int` with `php_charmask`, `chunk_split`; `ext/standard/type.c` `is_bool`):

- `round`, the constants `PHP_ROUND_HALF_UP` (1), `PHP_ROUND_HALF_DOWN` (2), `PHP_ROUND_HALF_EVEN` (3), `PHP_ROUND_HALF_ODD` (4), and the enum `RoundingMode`;
- `reset`, `end`;
- `is_bool`, `strtoupper`, `trim`, `chunk_split`.

## Boundaries & Constraints

**Always:**
- **Values and messages** are the ones PHP 8.5.11 gives on the host, recorded by a new probe.
- **round(num, precision = 0, mode = PHP_ROUND_HALF_UP).**
  - `num` is coerced as `Z_PARAM_NUMBER` (`numberParameter`), `precision` as an `int` (`intParameter`), clamped to C `int` as PHP does (`INT_MAX` / `INT_MIN`, then `INT_MIN + 1`).
  - `mode` is a `RoundingMode` case, or else an `int` coerced as `zend_parse_arg_long_weak`; anything else throws PHP's `TypeError` `round(): Argument #3 ($mode) must be of type RoundingMode|int, <type> given`. An int outside 1..8 throws PHP's `ValueError` `round(): Argument #3 ($mode) must be a valid rounding mode (RoundingMode::*)`, before `num` is rounded. Ints 5..8 are PHP's internal `AWAY_FROM_ZERO`, `TOWARD_ZERO`, `FLOOR` and `CEILING`, which PHP 8.5.11 accepts.
  - An int `num` with `precision >= 0` is returned as its float. Otherwise `_php_math_round` runs as written: non-finite or zero returned unchanged; `precision == 0` and integral returned unchanged; the floor/ceil extraction with the `tmp_value2` correction; `>= 1e16` returned unchanged; `php_round_helper` per mode; then division / multiplication by the power of ten for `|places| < 23`, else PHP's `"%15fe%d"` text read back with a correctly rounded parse (a non-finite result returns `num`). `php_intpow10` is the exact table for 0..22 and a correctly rounded `10^n` above.
  - The result is a float: a `number`, marked `float()` when integral, `-0` included (`round(75.0, 2)` is `float(75)`).
- **RoundingMode** is PHP 8.4's pure enum as an AD-26 enum, in its own file, registered as `RoundingMode`, with the cases `HalfAwayFromZero`, `HalfTowardsZero`, `HalfEven`, `HalfOdd`, `TowardsZero`, `AwayFromZero`, `NegativeInfinity`, `PositiveInfinity` in that order, built like `SortDirection` (frozen cases, `name`, `cases()`, `new` throws PHP's `Error` `Cannot instantiate enum RoundingMode`). It maps to modes 1, 2, 3, 4, 6, 5, 7, 8.
- **reset(ref) / end(ref)** take a `Ref` (DIV-9.2) whose `value` is an AD-9 array, and return its first / last value, or `false` when it is empty. `ref.value` is left as it is (the runtime's arrays carry no internal pointer). A non-`Ref` throws a JS `TypeError`, as `array_shift`'s does. A `Ref` holding a scalar or null throws PHP's `TypeError` `reset(): Argument #1 ($array) must be of type array, <type> given` (the probe confirms PHP's text).
- **is_bool(value)**: `true` for `true` and `false` only.
- **strtoupper(string)**: ASCII `a`-`z` raised (`zend_string_toupper`); every other byte, so every non-ASCII character, is unchanged.
- **trim(string, characters = " \n\r\t\v\0")** works on UTF-8 bytes: the default list as PHP's fast path gives it; an explicit list through `php_charmask`, `x..y` ranges included and a malformed `..` handled as PHP does (its warning not reproduced, its `.` skipped). A result that splits a UTF-8 sequence throws a JS `TypeError`.
- **chunk_split(string, length = 76, separator = "\r\n")** works on UTF-8 bytes: a `length` below 1 throws PHP's `ValueError` `chunk_split(): Argument #2 ($length) must be greater than 0`; a `length` above the byte length returns `string . separator` (so `""` gives `separator`); otherwise every `length` bytes and the remainder each end in `separator`. A result that splits a UTF-8 sequence throws a JS `TypeError`.
- The string functions coerce as PHP's `string` / `int` parameters (`stringParameter`, `intParameter`) and refuse a lone surrogate with a JS `TypeError`, as the existing string functions do.
- **Tests.** The new XT cases use `xaravelTest` and `@xaravel/assert`. A probe records every value PHP gives. A recompute case checks every probe label against the runtime, and a fresh-process case checks that the root and `@xaravel/runtime/php` export each new name as the same object.

**Never:**
- Change an existing export or behaviour.
- Add `RoundingMode` to `Symbol.for('xaravel.php.classes')`; like `SortDirection` it stays out.
- Port `reset` / `end` on an object (PHP 8.1 deprecated it): an object that is not an array throws a JS `TypeError` naming the unported form. Not ported either: PHP's warnings (`php_charmask`'s range warnings).
- Import `@xaravel/contracts` (AD-2), touch `conformance/**`, `decisions/**`, PORTING.md or another package, add a DIV clause, or change an existing assertion.
