## Intent

**Problem:** `guardWrite` in Macroable reads only `currentFrame().kind` (retro finding S1). A `test` frame opened inside a `request`, `job` or `command` unit takes a macro write, against DIV-11.2. A `unit` or narrow frame nested in a real test frame throws, though ESC-11.1-5's second bullet lets it write to the test frame. The runtime has no read of the frame chain (ESC-11.1-3).

**Approach:** `@xaravel/runtime/scope` exports `frameKinds(): readonly string[]`: the kinds of the active frame chain, innermost first, unit and narrow frames, parents only (origins not followed), frozen, `[]` with no frame. ESC-11.1-3 lets the runtime change pick this form. `runInNarrowFrame` refuses the kind `test`, so `test` in the chain always means a test unit. `guardWrite` passes a write only when `frameKinds()` contains `test` and none of `request`, `job` or `command`. Otherwise it throws `ScopeFrameException`. The write itself still goes through `frameStatic`, which routes it as AD-5.8 says.

## Design Notes

`ESC-11.1-5`'s two bullets disagree on a `unit` nested in a test frame. The item settles it: such a unit writes. The item's text asks for "no request, job or command frame between" the test and the innermost frame. The retro's item 1 also asks for a throw "under a request, job or command frame anywhere in the chain". Both hold only when the chain has a `test` and no `request`/`job`/`command` at all, which is the rule built here. Routing stays with `frameStatic`: a write from a child of the test frame, or from a narrow frame, lands in the test frame, but a unit nested two deep keeps its own write (AD-5.8). That write is still discarded no later than the test ends, so AD-5 holds. The docs say this.
