## Intent

**Problem:** Story 9.1's Scope Frames are all alike: every `runInFrame` opens a fresh, isolated frame, nothing waits for work a unit leaves behind, and Bun 1.4.3 drops the frame in async-generator bodies and `type: "direct"` streams (OQ-11 probes). AD-5.8, AD-5.9 and AD-5.1 need unit, narrow and child frames, an end-of-unit `defer` list, and frame propagation into streams and timers before any transaction, embedded test request or destructor terminal can be built.

**Approach:** Extend `@xaravel/runtime/scope`: frames form a parent chain; `runInFrame` opens a unit frame (a child unit when a unit frame encloses it), `runInRootFrame` a root unit frame, `runInNarrowFrame` a narrow frame over declared slots; `frameDefer(promise)` adds to the innermost unit's defer list, which `runInFrame` drains before an async body's unit ends; `bindToFrame`, `frameStreamSource` and `frameAsyncGenerator` wrap callbacks, stream sources and async generators with `AsyncLocalStorage.snapshot()`.

## Boundaries & Constraints

**Always:** edit only `packages/runtime/**`, this spec, the Story's status lines and manifest status. One `AsyncLocalStorage` (AD-5.1). Sync stays sync; no `T | Promise<T>` return (AD-6); no new exported Promise-returning function. `null`, never `undefined`, from public functions (AD-9). The three slots a child of a `test` frame keeps are exactly AD-5.8's request, route and CSP nonce, exported as fixed keys. Every 9.1 behaviour of a root frame (XT-runtime-1..4) keeps holding.

**Never:** overlays, `currentFrame()?.app` or `frameStatic` (Story 9.3); the Registry beyond 9.1 (Story 9.4); patching `setTimeout`, `ReadableStream` or `AsyncLocalStorage.prototype`; the HTTP kernel's `Bun.serve` error path (ESC-8.3-2, the http Component); editing `conformance/**`, `tools/**` or another package.

## Design Notes

- **Owner frame of key K from frame F:** narrow F → F if K is declared, else the owner from F's parent (none → no owner); unit F whose nearest enclosing *unit* frame is a `test` frame → F if K is one of the three child slots, else the owner from that parent; any other unit F → F. Write: store at the owner; no owner → `ScopeFrameException`. Read: the first frame from F up the chain that holds K; if none, `init()` stored at the owner (unstored if there is none). So a child of a non-test unit reads its parent's values until it writes its own, and a mutable `init()` value lives where writes would go.
- **Kinds:** `runInFrame(kind, fn)` is a unit frame (`kind` is a label: `test`, `unit`, `job`, …); `test` is the only kind with child-write semantics. Production kernels and `interleave` use `runInRootFrame`.
- **Drain:** when `fn` returns a thenable, `runInFrame`/`runInRootFrame` return `drain(result)`: await the body, then repeatedly await every deferred promise not yet awaited (a deferred promise may defer more), then mark the unit ended. Settles with the body's value; rejects with the body's error, else the first deferred rejection in registration order. A sync body that leaves deferred promises throws `ScopeFrameException`. `frameDefer` in a narrow frame adds to its nearest unit's list. Deferred promises get a handler at registration, so none is an unhandled rejection.
- **Wrappers** use `AsyncLocalStorage.snapshot()` (AD-5.1 names bind/snapshot) and keep `this`: `bindToFrame(fn)` returns `function (...a) { return snap(() => fn.apply(this, a)); }`. Outside any frame they return their input's behaviour unchanged (the snapshot restores "no frame"). Timers are `setTimeout(bindToFrame(cb), ms)`; the runtime patches no global.
