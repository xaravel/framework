# Story 10.2: Port the contracts for the core and service namespaces

<intent-contract>

## Intent

**Problem:** `@xaravel/contracts` has only the token mechanism and the PSR interfaces. Phase 1–5 packages need the `Illuminate\Contracts` interfaces of 19 namespaces (Support, Container, Config, Foundation, Pipeline, Events, Bus, Queue, Cache, Redis, Encryption, Hashing, Filesystem, Process, Translation, Validation, Debug, Concurrency, JsonSchema): 81 interfaces and 9 exception classes at the Pin.

**Approach:** Port each one to `@xaravel/contracts/<ns-kebab>` with Story 10.1's `contract()` shape, keeping Upstream names, parameters, parents and async-ness (AD-6), and declare a structural interface for each concrete type a contract names (AD-1.2). Cover XT-contracts-5 and XT-contracts-6 with Xaravel Tests. XT-contracts-7 (zero unexplained API-surface members) waits on `conformance/escalations/ESC-10.2-1.md`: three Upstream static rows cannot be declared on an interface or a token. So this Story ends `blocked` on that Escalation, with everything else merged.

## Boundaries & Constraints

**Always:**
- **Files.** One contract per file, `packages/contracts/src/<ns-kebab>/<ShortName>.ts`, with the PSR shape: `declare const XBrand: unique symbol;`, `export interface X [extends …] { readonly [X.brand]: true; … }`, `export const X = contract<X, typeof XBrand>("<FQCN>", members, parents);`. A header comment names the Upstream FQCN. `<ns-kebab>` is the `SUBPATH_EXPORTS` name: `support container config foundation pipeline events bus queue cache redis encryption hashing filesystem process translation validation debug concurrency json-schema`. Each subpath has `src/<ns-kebab>/index.ts` with named re-exports (value and type) of every contract and exception class in it, and `package.json` `exports` gains exactly `"./<ns-kebab>": "./src/<ns-kebab>/index.ts"` for the 19. Dependencies stay `{ "@xaravel/runtime": "workspace:*" }`.
- **Members.** A token's `members` lists its FQCN's `kind: "method"` rows from `conformance/api-surface/contracts.jsonl` in file order, each with its raw PHP parameter names in row order (`default` stays `default`). Declared methods only, as the rows and Story 10.1's PSR tokens do; never a parent's methods.
- **Parents.** `parents` is the contract tokens Upstream's `extends` names, in Upstream order: an `Illuminate\Contracts` token or a `@xaravel/contracts/psr` token (`Container\Container` → `[ContainerInterface]`, `Cache\Repository` → `[CacheInterface]`). A PHP built-in parent is no token and records no parent; the TS interface extends its structural form instead: `Countable` → `count(): number`, `ArrayAccess` → `offsetExists/offsetGet/offsetSet/offsetUnset`, `IteratorAggregate` → `[Symbol.iterator](): Iterator<unknown>`, `Stringable` → `toString(): string`, `Throwable` → `Error`. These come through `extends` of a shared structural type, never as members declared in the contract, so the API-surface tool sees no extra member.
- **TS signatures.** Upstream method and parameter names (already camelCase), except a reserved word, which takes a descriptive name noted in the docblock (`$default` → `defaultValue`). Optional and variadic exactly as the rows. A method with two or more optional non-variadic parameters also has an options-object overload keyed by the camelCase names of the optional parameters (AD-26): the positional signature, then `(required…, options?: { a?: A; b?: B })`. Types follow the PHP type or else the docblock: `string` → `string`; `int`/`float` → `number`; `bool` → `boolean`; `void` → `void`; `mixed`/untyped → `unknown`; `array` → `PhpArrayLike` (`readonly unknown[] | Readonly<Record<string, unknown>> | PhpArray`, AD-9); `iterable` → `PhpIterable`; `callable`/`Closure` → `Closure` (a function type); `@return $this` → `this`; `static` → `this`; nullable adds `| null`. A return is never `undefined`, and `T | Promise<T>` never appears. A docblock `@template` may become a TS type parameter, never narrowing what Upstream accepts.
- **Async (AD-6, DIV-1).** A method returns `Promise<…>` with a `@asyncRoot <Root>` JSDoc tag exactly when the table in Design Notes says so; every other method is sync. `packages/contracts/async-surface.json` is regenerated with `bun run async-surface contracts`.
- **Concrete types (AD-1.2).** A type outside `Illuminate\Contracts` and `Psr\SimpleCache`/`Psr\Container`/`Psr\Log` is a structural `interface` (or, for a function type or `stdClass`, a `type`) in `packages/contracts/src/structural/<ShortName>.ts`, whose header names the Upstream FQCN. It declares a subset of the Upstream class's own public members, each name and arity checked against the Upstream source (`conformance/upstream/framework/src/…`, or the vendor package's documented API), and never a member Upstream lacks. It has no brand and no token. Where the concrete class implements a contract this package ports (`Illuminate\Support\MessageBag`, `Illuminate\Validation\Validator`, `Illuminate\Process\ProcessResult`, `Illuminate\Redis\Connections\Connection`'s concrete subclasses), the contract is used instead. `DateInterval` and `CarbonInterval` use `src/psr/SimpleCache/DateInterval.ts`. `src/structural/` is not a subpath; each subpath index re-exports, as types, the structural types its contracts name.
- **Exception classes.** Each of the 9 `kind: "class"` rows is `export class X extends <Base> {}` in its own file, ending with `registerClass("<FQCN>", X)` (AD-10), where `<Base>` is runtime's `Exception`, `RuntimeException` or `InvalidArgumentException` from `@xaravel/runtime/php` as Upstream extends. `BindingResolutionException` and `CircularDependencyException` implement `Psr\Container\ContainerExceptionInterface`: they declare `get [ContainerExceptionInterface.brand]() { return true as const }`. `EntityNotFoundException`'s constructor `(type: string, id: unknown)` sets Upstream's message `Queueable entity [{type}] not found for ID [{id}].` (PHP string interpolation of `$id`).
- **Markers.** A contract with no methods (`ShouldQueue`, `ShouldBeUnique`, `ContextualAttribute`, …) is a brand-only token with `{}` members, checkable with `hasBrand(Class, Token)`.
- **Static rows** (second pass, ESC-10.2-1 option 1). `Filesystem\Filesystem`'s token takes the statics record `{ VISIBILITY_PUBLIC: "public", VISIBILITY_PRIVATE: "private" }` as `contract()`'s 4th argument (Upstream's values). `Events\ShouldBeDiscovered.ts` also exports `interface ShouldBeDiscoveredStatic { shouldBeDiscovered(): boolean }`, satisfied on an implementing class's constructor side. A static row is never in the token's `members`.
- **Tests.** XT-contracts-5, -6 and -7 use `xaravelTest` and `Assert` only. Each consequence string cites its consequence ids: XT-contracts-5 AD-1.1 and AD-6 (async tags), XT-contracts-6 AD-1.2, XT-contracts-7 AD-1.1 and AD-1.6.

**Second pass (ESC-10.2-1, -2, -4):**
- **`contract()` statics** (ESC-10.2-1). `contract<T, B, S>(fqcn, members = {}, parents = [], statics = {}, builtins = [])`. `statics` is a plain-object record of the contract's Upstream constants (string keys, values `string | number | boolean | null`); the token gets each as a frozen own enumerable property, so `Filesystem.VISIBILITY_PUBLIC === "public"`, and its type is `ContractToken<T, B> & Readonly<S>`. A key that names an existing token key (`brand`) or a non-record `statics` throws a `TypeError` naming `contract()`. A token without statics is unchanged.
- **`contract()` builtins** (ESC-10.2-4 and its 2026-10-23 clarification). `builtins` lists the PHP names of the built-in parents' methods, in this fixed order per parent and parents in Upstream `extends` order: `Countable` → `count`; `ArrayAccess` → `offsetExists`, `offsetGet`, `offsetSet`, `offsetUnset`; `IteratorAggregate` → `getIterator`; `Stringable` → `__toString`. Any other name, a duplicate or a non-array throws a `TypeError` naming `contract()`. A non-empty list is kept frozen at `CONTRACT_BUILTINS` (`Symbol.for('xaravel.contract.builtins')`, exported beside `CONTRACT_PARENTS`); an empty one sets no key (absent means none), so every existing token is unchanged. The three contracts with built-in parents pass theirs: `Support\MessageBag` `["count"]`, `Support\ValidatedData` `["offsetExists","offsetGet","offsetSet","offsetUnset","getIterator"]`, `Validation\ParameterizedRule` `["__toString"]`. `members` stays declared methods only.
- **Pipeline** (ESC-10.2-2 option 1). `Pipeline\Pipeline` declares both `then` overloads: `then(destination: Closure): Promise<unknown>` (tagged `@asyncRoot callback`, as now) and the `PromiseLike` form `then<R1 = unknown, R2 = never>(onfulfilled?: ((value: unknown) => R1 | PromiseLike<R1>) | null, onrejected?: ((reason: unknown) => R2 | PromiseLike<R2>) | null): PromiseLike<R1 | R2>`, so the interface is `PromiseLike`-compatible. Its `members` stay `{ then: ["destination"], … }` (the row). `async-surface.json` keeps #355's `thenable` lines for `send`, `through` and `via`; regenerating it changes nothing else. If the API-surface tool reports the second overload as a mismatch, that is a contract question: raise `conformance/escalations/ESC-10.2-8.md` (`contract`) for XT-contracts-7 and do not change the tool.
- **ESC-10.2-3, -5, -6** need no port change (getMessageBag stays sync, the Application split stands, rule methods keep `@asyncRoot callback`).
- **XT-contracts-5** is restored from the patch into `packages/contracts/tests/xaravel/namespaces.test.ts`, then extended: static rows are checked as statics (Filesystem's two constants equal Upstream's `const` values read from the PHP file; `ShouldBeDiscoveredStatic` is exported as a type and a class with `static shouldBeDiscovered()` satisfies it, checked by a compile-free runtime call), no longer filtered out as an exemption; each token's `CONTRACT_BUILTINS` is derived from the Upstream file's built-in parents through the mapping above (absent when none); and Mockery `Double.for` and PHPUnit `createMock` of `ValidatedData` can configure `getIterator` and `offsetGet` and of `MessageBag` `count`. Its Upstream-derived parts run only where `conformance/upstream/framework/src/Illuminate/Contracts` exists and warn otherwise, as XT-contracts-6 does (under `XARAVEL_UPSTREAM=require` they fail instead: third pass); its row-derived parts always run. The patch file is deleted in this PR.
- **XT-contracts-7** (`packages/contracts/tests/xaravel/api-surface.test.ts`): spawns `bun run api-surface --details contracts` from the repository root, and asserts that it exits 0, that its summary line parses, that at least one detail line names a Story 10.3 namespace (the tool really ran over the rows), and that no detail line (`missing`, `extra`, `mismatch`, `renamed`, or any other) names an FQCN in the 19 namespaces, listing every such line on failure. It reads only committed files, so it runs everywhere.

## Design Notes

**Async table (AD-6, DIV-1).** Roots are `Cache\Store`, `Queue\Queue`, `Filesystem` IO, Redis commands and `Process` runs; a method is async iff it reaches one or takes a callback DIV-1 lets be async (validation rules, listeners, middleware/pipes, `Cache.remember*`). Everything not listed is sync, including all of Container, Config, Hashing, Encryption, Translation, Support, Debug, Pipeline `send/through/via`, and `Process\ProcessResult`.

| Contract | Async methods | `@asyncRoot` |
|---|---|---|
| Cache\Store | get many put putMany increment decrement forever touch forget flush (not getPrefix) | `Cache\Store.<same method>` |
| Cache\Repository | pull put add increment decrement forever touch forget; remember sear rememberForever | `Cache\Store.<same method>`, except pull → `Cache\Store.get` and add → `Cache\Store.put`; `callback` for the three remember forms |
| Cache\Lock | get block release forceRelease (not owner) | get and block → `Cache\Store.put`, release and forceRelease → `Cache\Store.forget` (Upstream's CacheLock) |
| Cache\CanFlushLocks | flushLocks | `Cache\Store.flush` |
| Queue\Queue | size pendingSize delayedSize reservedSize creationTimeOfOldestPendingJob push pushOn pushRaw later laterOn bulk pop | `Queue\Queue.<same method>` |
| Queue\ClearableQueue | clear | `Redis\Connection.command` (RedisQueue) |
| Queue\Job | fire | `callback` |
| Queue\Job | delete release fail (not markAsFailed) | `Redis\Connection.command` (RedisJob deletes or releases through its queue's connection) |
| Queue\EntityResolver | resolve | `Database\ConnectionInterface.select` (a model query) |
| Bus\Dispatcher | dispatch dispatchSync dispatchNow | `callback` (handler), dispatch also queues |
| Bus\QueueingDispatcher | dispatchToQueue | `Queue\Queue.push` |
| Bus\QueueingDispatcher | findBatch | `Database\ConnectionInterface.select` (batch repository) |
| Events\Dispatcher | until dispatch flush | `callback` (listeners) |
| Pipeline\Pipeline | then | `callback` (pipes) |
| Pipeline\Hub | pipe | `callback` |

| Redis\Connection | subscribe psubscribe command | `Redis\Connection.<same method>` |
| Process\InvokedProcess | wait waitUntil | `Process\InvokedProcess.<same method>` |
