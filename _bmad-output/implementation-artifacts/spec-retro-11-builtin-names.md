## Intent

**Problem:** Retro finding L1: `install` skips any name `in` the target, so a macro named like an inherited JS member (`toString`, `valueOf`, `hasOwnProperty` on instances; `call`, `apply`, `bind`, `toString` on the class) is registered but never called, where PHP's `__call` / `__callStatic` would run it; and a class's own built-ins (`prototype`, `name`, `length`, `constructor`) are silently ignored. Finding L2: `mixin` calls a mixin's static method with `this` the mixin instance, where PHP's `static::` is the class.

**Approach:** Apply the Maintainer's ruling (`decisions/MAINT-2026-10-25-epic-11-item-5.md`, DIV-12.11): `install` yields only to a member declared below `Object.prototype` / `Function.prototype`; `macro()` throws `InvalidArgumentException` for the four reserved names; `mixin` calls static methods with `this` the mixin's class, skips only the mixin's own `constructor`, and no longer silently drops a mixin method whose name JS also builds in. Document it and cover it with XT-macroable cases.

## Boundaries & Constraints

**Always:** Edit only `packages/macroable/**` and this item's records under `_bmad-output/implementation-artifacts/`. Keep every existing assertion and Upstream message. A member the class, its parents or the trait declare still wins over a dispatcher. `hasMacro()` of a reserved name returns `false` because nothing can register it.

**Never:** Override a class's `prototype`, `name`, `length` or a prototype's `constructor`. Touch `conformance/**`, `decisions/**`, `tools/**`, another package, or the item's `action`/`owner`/`epic`. Use a Proxy (AD-7, AD-26). Weaken or remove an assertion.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Inherited instance name | `G.macro("toString", fn)`; `new G().toString()` | runs `fn` with `this` the instance; also `valueOf`, `hasOwnProperty`; subclass instances too | none |
| Inherited static name | `G.macro("call", fn)`; `G.call()` | runs `fn` with `this` `G`; also `apply`, `bind`, `toString`; subclass static calls too | none |
| Declared member wins | class or parent declares `toString()` / `static bind()` | the declared member runs; macro still in `hasMacro` and `__call` | none |
| Reserved name | `macro("prototype" \| "name" \| "length" \| "constructor", fn)` | throws; class's `name`, `length`, `prototype`, `prototype.constructor` unchanged; `hasMacro` false | `InvalidArgumentException` naming the word, asking for another name, citing DIV-12.11 |
| Flushed inherited name | `toString` registered then `flushMacros()` | `new G().toString()` throws | `BadMethodCallException` `Method <fqcn>::toString does not exist.` |
| Static mixin method | mixin class `static make() { return this.helper(); }` | `make` runs with `this` the mixin's class; result registered | none |
| Mixin with JS-named methods | mixin declares `toString()`; own `constructor` | `toString` registered and dispatches; `constructor` skipped | a mixin method named `name`/`length`/`prototype` throws as `macro` does |

## Code Map

- `packages/macroable/src/Traits/Macroable.ts:91-96` -- `install`: replace `name in target` with a walk of own properties from `target` up to (excluding) `Object.prototype` (instance side) or `Function.prototype` (static side), or `null`. `installDispatchers` (`:99`) passes the stop.
- `Macroable.ts:99-118` -- `installDispatchers`: when `name` resolves on `stop` (a function JavaScript gives every object or function: `Object.prototype.toString`, `Function.prototype.call`, …), the dispatcher falls back to that built-in, called with the same `this` and arguments, whenever the active frame's table (`macros(klass).get()`) has **no entry** for `name` (`!table.has(name)`); otherwise it forwards to `__call` / `__callStatic` as now. A read with no active frame returns an empty table (`frameStatic` `get`, `packages/runtime/src/scope/scope.ts:220-232`), so it falls back too. A dispatcher for any other name is unchanged. (Loop 2:) The entry check reads the **receiver's** table, not the closure's `klass`: `macros(this)` on the static side and `macros(this.constructor)` on the instance side, so a using class below another using class (`class B extends mixin(A, Macroable)`, whose `install` finds A's dispatcher and is skipped) still runs its own built-in-named macro. A receiver that does not use the trait (`usingClass` throws, e.g. `G.prototype.toString.call({})`) falls back to the built-in.
- `Macroable.ts` `installDispatchers` / `install`, accessor-backed names (loop 2) -- when the member `name` resolves to on `stop` is an **accessor** (`Object.getOwnPropertyDescriptor` along `stop`'s chain has `get`/`set`: `__proto__` on both sides, `caller` and `arguments` on `Function.prototype`), install an accessor, not a data property: its getter returns the dispatcher function while the receiver's frame table has an entry for `name`, and otherwise returns `Reflect.apply(original.get, this, [])` (throwing as the original does); its setter defers to `original.set` with the same receiver when there is no entry (and when there is one too, so `x.__proto__ = p` still sets the prototype). ## Design Notes

Dispatchers stay on the class across frames (DIV-12.10), but macros are discarded at the end of their test (DIV-11.2). A dispatcher over a JavaScript built-in therefore must not throw where the active frame has no entry for its name, or one test's `toString` macro would break `String(x)` in every later test. It falls back to the built-in; an entry (a macro, `null`, or a `flushMacros` tombstone) forwards to `__call` / `__callStatic`. So inside the frame, direct calls behave as PHP (the macro runs; flushed, `BadMethodCallException`), and in any frame without the name the class behaves as it did before any macro. JavaScript's implicit calls (`String(x)`) reach the dispatcher while the entry exists; that is a consequence of DIV-12.11's install, documented as such, not PHP behaviour.

```ts
// sketch, instance side
const builtin = (Object.prototype as Record<string, unknown>)[name];
function (this: Macroable, ...args) {
  if (typeof builtin === "function" && !macros(klass).get().has(name)) return Reflect.apply(builtin, this, args);
  return this.__call(name, args);
}
```
