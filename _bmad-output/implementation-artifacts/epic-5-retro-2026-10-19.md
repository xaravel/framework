### Diff-scope review (adversarial, edge-case, verification-gap lenses)

The review weighted the boundaries between Stories. Checked and sound: the worktree key is the first 8 hex of SHA-256 over `<realpath>\n<creation id>`; the Variant vocabulary matches `backends.ts` and `ALPHA_VARIANTS`; the Expectations line format 5.1 writes is the one the harness, reasons check, ratchet and story-check read; fast runs add `mode=fast` to SUMMARY and no CI job passes `--fast`; the bot PR identity rule holds and `apply` runs ownership's `botValueProblems` before it writes.

- **C1. The `ratchet` PR job runs fork-PR code under `pull_request_target` with no same-repository guard** (`.github/workflows/ratchet.yml:40`, `:93-98`: it checks out `head.repo.full_name` at the head SHA and runs that PR's tests). The repository is public. `pull_request_target` skips the first-time-contributor approval, so any fork PR runs its own code in the base branch's cache scope, where it can poison cache entries that later `main` workflows restore. `oracle.yml:261` already has the guard (`head.repo.full_name == github.repository`). Should-fix, security. *Fix now* (action item 1).
- **H1 / C2 / C3. The done check's `full-run` clause does not test what its name says.** `isFullRun` checks only that SUMMARY lacks ` mode=fast` (`conformance/harness/harness.ts:219-221`). The PR `ratchet` job's last SUMMARY comes from a filtered run (`ratchet run --scope`, then `ratchet story`), so a filtered run satisfies "the last CI run was a full run"; the merge-queue run is the only full one and is on another SHA (H1). The clause also requires `differ=0` from that SUMMARY (`story-check.ts:319-341`), while the Ratchet counts unexpected passes owned by no Story, or by another open Story, as warnings that still count as differences (`ratchet.ts:236-237`). A Story with empty `test_ids`, such as 10.1, then fails `full-run` over a difference it may not fix (C2). And it never checks the job's conclusion, so a run that ended `UNEXPECTED-FAILURE harness exited <n> with no counted difference`, or was cancelled after the closure step, still prints `differ=0` (`ratchet.ts:238-240`, `story-check.ts:424-435`) (C3). The meaning of "full run" on a PR is a contract question for the Maintainer; the conclusion check is a plain fix. *Fix now* (action items 2 and 3 split it).
- **H2. `--story` and the done check match Test IDs exactly, while ownership lets a bare `X` cover its dataset rows `X#<key>`** (`conformance/harness/select.ts:74`, `harness.ts:436-441`, `story-check.ts` `assignedLines`, against `tools/ownership/ownership.ts:556-560` `covers`). 4,348 Inventory IDs are such rows. A Story that lists `X` may edit and is blamed for its rows, but `ratchet story` and the done check grade none of them. *Fix now* (action item 5). Lesson: two tools that select by Test ID must share one matcher.
- **H3. Every Variant run executes every Ported Test; results on Variants a test does not belong to are dropped silently** (`harness.ts:605` `let files = allFiles`; `compare.ts:262`). Nothing in `packages/` reads `XARAVEL_VARIANT`. With the first Phase 1 ports this costs up to 13 runs of the whole suite, hides hangs and errors on non-member Variants, and lets the `sqlite` Variant start from state the `none` and `pgsql` runs left in `.cache/sqlite`. This is a design gap across AD-15 and AD-17. *Fix now* by raising an Escalation before Phase 1 ports land (action item 6).
- **C4. The devcontainer job fails on harness differences the Ratchet treats as warnings** (`.github/workflows/devcontainer.yml`, step "Run the harness inside the container", exits with the raw `bun run harness` status). Once `main` carries a warned unexpected pass, the nightly devcontainer job and every `.devcontainer/**` PR go red. Advisory job. *Fix now* (action item 11).
- **C5 / C6. Bot proposal edge cases.** A bot branch that still exists blocks the same proposal forever (`tools/bots/bots.ts:567-571`); `deleteBranchOnMerge` is on, but a closed, unmerged PR still blocks the key, and a `pending` escalation proposal is dropped rather than queued (`:573-577`). `ESC-bot-<n>` numbering lists `conformance/escalations` through the contents API (`:532`), which caps at 1,000 entries, so the next number can collide once the directory grows. *Fix now* (action item 12).
- **H4. A stale harness lock in the devcontainer's cache volume is never reclaimed** after the container is recreated with a new hostname (`isolation.ts:227`; `.devcontainer/compose.yaml` sets no `hostname`). *Defer* (document or pin the hostname when the devcontainer is next touched).
- **H5. `fewer_assertions` clauses are parsed as YAML numbers** (`harness.ts:294`): `[2.10]` becomes `"2.1"`. It fails closed (a spurious FLOOR), and no DIV record exists yet. *Defer* to Story 8.1, which writes the first ones; quoted clauses avoid it.
- **C7. Branches outside `story/`, `planning/` and `bot/` skip every scope and line-ownership rule** (`tools/ownership/ownership.ts:120`, `:1006`). This predates Epic 5, but the Ratchet now relies on ownership to downgrade foreign passes to warnings. *Defer*; it overlaps the open Epic 1 identity item 12, which the Maintainer takes at the Epic 8 checkpoint.
- **Verification gap:** XT-conformance-100 (`skip-reasons.test.ts:331`) only greps `conformance/README.md`. Acceptable for a documentation AC.
