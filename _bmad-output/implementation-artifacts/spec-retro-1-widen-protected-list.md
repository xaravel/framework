## Intent

**Problem:** AD-16 (amended by the Maintainer ruling `decisions/MAINT-2026-10-17-epic-1-items.md` item 14, retro finding D11) now protects `.bun-version`, the root `LICENSE`, `.claude/` and `**/CLAUDE.md` in any letter case. `conformance/protected-paths` does not list the first three, and the check matches `**/CLAUDE.md` case-sensitively, so `claude.md` or `packages/x/Claude.md` is unprotected.

**Approach:** Add `/.bun-version`, `/LICENSE` and `/.claude/` to the list, then regenerate `.github/CODEOWNERS` with `bun run protected-paths:codeowners`. Make `isProtected` match **inclusion** entries case-insensitively while exclusions stay case-sensitive. That covers every letter case of `CLAUDE.md` without new list syntax. It can only add Protected paths, never remove one.

## Boundaries & Constraints

**Always:** `matches()` (exported, used by other tests) and `renderCodeowners()` / `checkMirror()` output stay byte-for-byte unchanged. Exclusions stay case-sensitive. New entries go after `/.gitattributes` and `**/CLAUDE.md`, in spine order. Keep every existing XT-conformance-17..21 assertion and add to it. Update only the expected-list literal in XT-17, which the ruling requires. CODEOWNERS is generated, never hand-edited.

**Never:** No new list marker or pattern syntax. Main's copy of the tool judges this PR (`pull_request_target`) and parses the head list, so new syntax would read as `codeowners drift`. No change to the CODEOWNERS header or render format, for the same reason. No edit to `AGENTS.md`, the spine, `tools/ownership/` or `.github/workflows/protected-paths.yml`. No `CLAUDE.md` created anywhere.

## Design Notes

GitHub CODEOWNERS is case-sensitive and supports no `[ ]` ranges, so CODEOWNERS keeps the literal `**/CLAUDE.md`. Only the `protected-paths` check (the required gate) applies any-case matching. Folding inclusions only, never exclusions, makes the new protected set a superset of the old one.
