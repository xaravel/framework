### Diff-scope review (adversarial, edge-case, verification-gap lenses)

- **R1. `createMock` returns a Mockery mock, but upstream tests drive PHPUnit's MockObject API on it** (4.4 meeting 4.5, high). `packages/assert/src/Framework/TestCase.ts:131-139` returns `globalThis[Symbol.for('xaravel.mockery.mock')](type)`. In the Upstream snapshot, 11 files under `conformance/upstream/framework/tests` call `createMock(`, and 65 `->method(` calls sit within two lines of them (plus `->expects(` and `->willReturn(`). Those are PHPUnit `MockObject`/`InvocationMocker` methods. Mockery's mock has no `method()` or `willReturn()`, its `expects()` means something else, and `TestCase` has no `once()`/`any()`/`getMockBuilder()`. A ported test doing `this.createMock(X).expects(this.once()).method('foo')` throws. The design comes from `epics.md:114` ("`createMock` goes through `@xaravel/mockery`"), and `decisions/ESC-4.4-1.md` calls it "PHPUnit's delegation to Mockery", but PHPUnit does not delegate `createMock` to Mockery. XT-assert-13 checks only Mockery-style expectations. *Fix now* as a spec reconciliation (Maintainer, item 8).
- **R2. Mockery matches a `function` value as if it were a class** (4.5 meeting 4.6, high). `packages/mockery/src/Mockery/Expectation.ts:417-422` (`8877869`) uses `isClass(expected)`, and `isClass` (`support/values.ts:47`) is true for any function with an object `prototype`, including `function handler(){}`. 4.6 added `isClosure` (`values.ts:56`) for exactly this reason but never fixed `_matchArg`. A probe (`/tmp`) showed `with(function handler(){})` matching the call `run('handler')`; in PHP a Closure never equals a string. *Fix now* (item 1).
  - *Status 2026-10-18 (orchestrator):* the fix is built, reviewed and green in #126, but cannot merge. A retro action item has no `stories/<id>.md` manifest for a `story/*` branch, and the orchestrator may not invent one. Waiting on the Maintainer to say how retro code fixes reach `packages/**`, for example a Story id and manifest per item, or a ruling exception. Items 2, 3 and 4 also edit `packages/**` and meet the same rule.
