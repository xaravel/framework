## Intent

**Problem:** Each generated package `tsconfig.json` has `rootDir: "src"` and `include: ["src/**/*.ts"]` (`tools/scaffold/scaffold.ts` `generateTsconfig`), so no `tsc -b` ever checks a package's `tests/**`, where every Ported and Xaravel Test will live. Separately, the graph check allows a guarded `import()` of an optional peer (`tools/graph/graph.ts:317-320`), but the scaffolder never references peers, and nobody has shown that such an import type-checks under `tsc -b` (retro finding D9).

**Approach:** Generate each package tsconfig with `rootDir: "."` and `include: ["src/**/*.ts", "tests/**/*.ts"]`, regenerate all 53 with `bun run scaffold`, and update XT-conformance-9. Add XT-conformance-39, a temp-root fixture that pins both behaviours under the real `tsc -b`: a guarded `import()` of an unreferenced optional peer type-checks (and a wrong member through it is still an error), and a type error in a package `tests/` file fails the build naming that file. Probe result at planning time (TS 7.0.2, real repo): a guarded `import("@xaravel/http")` from `collections` builds with exit 0, and `.y` on it fails with TS2339, so `references` stay dependencies-only. Adding peers as references is not possible: it creates 52 reference cycles (for example collections → http → collections).

## Boundaries & Constraints

**Always:** Package tsconfigs stay generated and equal to `generateTsconfig` output; every other field (composite, emitDeclarationOnly, outDir and tsBuildInfoFile under `.cache/tsc/<name>`, `types: ["bun"]`, dependency-only sorted references) is unchanged. The fixture test runs the repo's pinned `tsc` (`node_modules/typescript`) via `bun --bun`, uses the real `generateTsconfig` and `tsconfig.base.json`, and cleans its temp dir. Record the probe result in this spec; leave the done spec-1-2 unchanged.

**Never:** No peer references, no per-package second tsconfig, no change to `tsconfig.base.json`, the root `tsconfig.json` other than what `scaffold` regenerates, `tools/graph/`, `AGENTS.md`, the spine, SPEC, PRD or `epics.md`. No removed or weakened assertion.

## Probe Result

TS 7.0.2, `tsc -b`, with no peer `references`. Run at planning time on the real repo, and pinned by XT-conformance-39 in a temp root:
- A guarded `import()` of an unreferenced optional peer builds with exit 0. Reading a missing member through it still fails with TS2339 in `src/index.ts`. So `references` stay dependencies-only, which resolves spec-1-2's deferred finding.
- With `rootDir: "."` and `tests/**/*.ts` included, a type error in `tests/xaravel/x.test.ts` fails the build and names the file. A well-typed test that imports `bun:test` builds with exit 0.
- A package test can statically import an unreferenced workspace devDependency, even a cyclic one (`b` depends on `a`, and `a`'s test imports `b`). It builds with exit 0 and no output, and the import stays typed.
- With `include` reverted to `src/**/*.ts`, the test-file row of XT-conformance-39 fails (the build exits 0), so the test detects that regression.
