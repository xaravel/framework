### Diff-scope review (adversarial, edge-case, verification-gap lenses)

Three sub-agents reviewed 7.1, 7.2, and 7.3 with 7.4 plus their boundary, with probes under `/tmp/retro7-{a,b,c}/`; no repository file changed. Checked and sound: the Conformance Rate's denominator is every Expectations line, `not-ported-yet` included, with `rate: null` at 0 pairs; all statuses and Skip Reason kinds appear with zeros, and `fail-known` is never a skip; quarantined, fail-known, intentional-divergence, not-ported-yet and blocked-by count as not passing; `ALPHA_VARIANTS` has one source (`tools/inventory/inventory.ts:93`); the history is plumbing-only and pushes fast-forward with retries; a Pin change starts a new chart series with a marker; HTML is escaped (`& < > " '`) and every link is prefixed with the repository's blob URL, so a `"><script>` or `javascript:` value in an Escalation, Quarantined line or API-surface record never reaches a page raw; `dashboard.yml` triggers only on `push` to `main`, pins actions by SHA, keeps `contents: read` at the top with `contents: write` only on the dashboard job, uses `persist-credentials: false` and gives the token to the history and publish steps only; the open-Escalation rule matches `tools/escalations` (sha256-bound decisions); the server locks down before it loads the SDK (`server.ts` imports only `./lockdown`); `node:fs` writes, `child_process`, `cluster`, `Worker`, `bun:sqlite`, `Bun.spawn`, `Bun.write` and `process.binding("fs")` writes are refused; `..`, `file:` URLs, `{flag: "a"}` reads and out-of-scope `existsSync` are refused; the only dependency is `@modelcontextprotocol/server` at exactly 2.3.1.

- **L1. The lockdown's `Bun` denylist misses members that read, write or connect.** `BUN_REFUSED` (`tools/boost-framework/src/lockdown.ts:49`) and `GLOBALS_REFUSED` (`:52`) are fixed lists. After `lockdown(root)` the probes showed: `Bun.fetch("file:///etc/hosts")` returned the file (only `globalThis.fetch` is replaced); `process.getBuiltinModule("node:sqlite").DatabaseSync` created and wrote a file; `Bun.Archive.write` wrote a tar; `new Bun.FileSystemRouter({dir: <root>/tools})` listed out-of-scope directories; `import("/etc/hosts", {with: {type: "text"}})` and `require("<root>/package.json")` read out-of-scope files. `Bun.secrets`, `Bun.redis`, `Bun.WebView` and `Bun.Terminal` are untouched. `docs/framework-mode.md:201-206` lists none of these as open, and `spec-7-4:171` claims every `Bun` member that writes, spawns or touches the network refuses. The static guard (XT-boost-4) keeps `src/` from naming them, so only the SDK or zod could reach them, and the lockdown is the backstop there. *Fix now* (action item 1).
- **L2. A crafted glob stalls the stdio server.** `globToRegExp` turns each `*` into `[\s\S]*` (`tools.ts:71`) with no length or wildcard cap, and `inventory.get` matches it synchronously against about 22,000 Inventory IDs (`tools.ts:114`). Probe on one 90-character ID: 8 `*t` pairs took 9.9 ms, 10 took 58 ms, 12 took 192 ms, about ×3 per pair, so `"*t".repeat(14) + "!"` blocks the server for minutes. The harness's `--id` uses the same function (`conformance/harness/select.ts:40`). *Fix now* (action item 2).
- **L3. XT-boost-6 does not check that each tool succeeds.** Its comment says "Each tool was called successfully at least once", but it asserts only `0 < errors < calls.length` over all calls (`boost-framework.test.ts:1123-1125`), so a tool that always errors still passes. *Fix now* (action item 3).
- **L4. The dashboard workflow does not run `expectations:check` before the report.** The aggregator walks Expectations lines only (`report.ts:200-232`); an Inventory ID with no line silently leaves the denominator, and only `expectations:check` in `ci.yml:128` catches it. A Pin bump that lands before its Expectations lines would publish a shrunken denominator. *Fix now* (action item 6).
- **L5. A re-run of an older dashboard run publishes stale figures and appends history out of order.** Neither `publish.ts:97-112` nor the history append checks that the source commit is the `main` tip or descends from the last published one. Probe: records `[v1, v2, v1 (re-run), v2]` drew three Pin-change markers where one was real. *Fix now* (action item 6).
- **L6. Pushes queued behind a running dashboard job lose their history records** (GitHub keeps one pending run per concurrency group). Documented at `dashboard.yml:26-30`. *Accept*.
- **L7. The Epic page's per-Story diff counts every commit whose subject starts `<id>: `**, blocked attempts and retro follow-ups included (Story 2.6 shows 4 commits, +28,249 −22,070), and `--no-renames` counts a rename as add plus delete (`site.ts:361`, `:402`). `began` ignores planning commits just before the first Story (`site.ts:419-420`). *Accept*; document with action item 5.
- **L8. `writeSite` deletes any `--out` directory holding a `.nojekyll`** (`site.ts:753-758`). *Accept*; tighten if `--out` is ever pointed outside `.cache/`.
- **L9. Minor:** Boost sorts Escalations with `compareUnits`, the dashboard numerically (`site.ts:263`), so `ESC-10.1-1` precedes `ESC-2.4-1` in Boost only; `str()` turns a non-string argument into `null`, so `{story: 1}` reports `got null` (`tools.ts:56`, `:495`); a symlink swapped between `inScope` and the read is followed (documented); the report is stamped with `HEAD` but reads the working tree (`report.ts:163-193`), and history keeps the first record per (commit, Pin). *Accept*.
