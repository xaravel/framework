- **S1. Story 14.5's deferral of `combine` / `zip` iterator cleanup to "the later LazyCollection Story" was never taken up.** Story 14.5 closed with `followup_review_recommended: true` and "The later LazyCollection behavior work must inspect coordinated ownership/exception ordering in combine/zip" (`spec-14-5-…md:1055`, `:1057`). Story 14.7's spec never mentions `combine` or `zip` (`grep` finds nothing), and the docs still say "`combine` and `zip` still coordinate manual iterators and can leave temporary input generators open on early exit. Their cleanup remains for the later LazyCollection Story" (`packages/collections/docs/collections.md:245`–`247`), though both LazyCollection Stories are done. `LazyCollection.combine` and `zip` hold `makeIterator` iterators with no `finally` (`packages/collections/src/LazyCollection.ts:1097`–`1147`). In PHP an abandoned generator's `finally` runs when it is destroyed; in JS it never runs unless `return()` is called, so a user generator passed to `combine` / `zip` and abandoned by `take` or `first` silently skips its cleanup. Probe at `24f70a08`: with a source `function* () { try { yield 1; yield 2; yield 3 } finally { closed++ } }`, `new LazyCollection([1, 2, 3]).zip(new LazyCollection(src)).first()` and the same with `combine` leave `closed` at 0, while `new LazyCollection(src).first()` gives 1. LESSONS (epic 1: a deferral must name a target whose ACs cover it; epic 11–12: a residual in the docs is not a DIV clause). *Fix now* (action item 1, `packages/collections`).
