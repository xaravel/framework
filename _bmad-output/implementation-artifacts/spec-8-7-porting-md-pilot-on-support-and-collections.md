# Story 8.7: `PORTING.md` pilot on Support and Collections

<intent-contract>

## Intent

**Problem:** FR-8.2 requires `PORTING.md` to be piloted on real Support and Collections tests and revised from the evidence before Phase 1 starts. Story 8.8's gate needs the pilot report on `main`. ESC-8.7-1's ruling fixes the Phase 0 reading of the three checks: type-check against declaration-only `.d.ts`, a static assertion floor, and the in-loop Fidelity Review.

**Approach:** Draw a seeded, stratified sample of at least 60 Test IDs, and have fresh-context translator agents port them using only `PORTING.md`, the DIV records, the public `@xaravel/assert`/`@xaravel/mockery` API, the generated `.d.ts` and the Upstream source. Then type-check the translations, measure the static floor and run `fidelity:review` on them. All of this lives on an unmerged `pilot/porting` branch. To `main` (this Story's PR) go `docs/porting/pilot-report.md`, the `PORTING.md` revisions the pilot caused, and XT-conformance-166/167, which check the report against the Inventory, the seed and `PORTING.md`.

## Boundaries & Constraints

**Always:**
- Sample: seed `pilot-8.7`. All 4 Mockery rows (`SupportCollectionTest::testToArrayCallsToArrayOnEachItemInCollection#0/#1`, `…::testJsonSerializeCallsToArrayOrJsonSerializeOnEachItemInCollection#0/#1`), then `sampleIds(pool, "pilot-8.7", n)` per stratum. The pools exclude the Mockery rows. The strata and sizes are: Collection provider rows 16, Collection plain 8, Arr 12, Str plain 8, Str provider 8, Stringable 8, for 64 in all. A stratum's pool is its file's Inventory ids (`conformance/inventory/{collections,support}.jsonl`) split on `#`.
- Translators get only those inputs (Approach) and record, per Test ID, every `PORTING.md` rule they applied and every point where `PORTING.md` did not decide. They never read other packages' source or earlier specs.
- Translations sit at their AD-15 paths `packages/{collections,support}/tests/ported/framework/tests/Support/<File>.test.ts` on `pilot/porting` only. Each file starts with the marker line `// pilot/porting: Story 8.7 pilot translation, never merged`.
- `.d.ts` files are generated by a script from `conformance/api-surface/{collections,support}.jsonl` and declare only. They live in `pilot/` on `pilot/porting` with its own `pilot/tsconfig.json` (`paths` maps `@xaravel/collections` and `@xaravel/support` to them). `tsc --strict -p pilot/tsconfig.json` must exit 0.
- Static floor (`pilot/floor.ts`): for each sampled id, count the assertion call sites by kind (`this.assert*`, `Assert.assert*`, `this.expectException*`) in its `portedTest` body. Every Inventory `assertions` kind must reach its count, or the shortfall carries an `adapted:DIV-<n>.<k>` marker. Mark an id `approximate` when the body loops or is shared by dataset rows.
- Pilot review: on a worktree of `pilot/porting`, `stories/8.7.md` lists the 64 ids as `test_ids` (on that branch only). Run `bun run fidelity:review review --story 8.7 --root <pilot worktree> --spec <this spec, absolute> --base <story/8.7 merge-base sha> --loop-cli claude`. Both verdicts must be `pass`. On a `reject`, fix the translations and re-run.
- Every ambiguity gets a `PORTING.md` revision placed inside an existing `##` section (the `porting:check` section list is fixed), and the report quotes the added sentence verbatim.
- Push `pilot/porting` to origin. The report records its full commit sha.

**Never:** Merge translations, `.d.ts` or pilot tooling into `main`. Implement any Collection/Str behaviour. Add `##` sections to `PORTING.md`, or edit `tools/porting`, the fidelity checklist or tool, or Expectations. Hand-edit Fidelity verdict records.
