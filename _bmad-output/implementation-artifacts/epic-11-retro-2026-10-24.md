### Diff-scope review (adversarial, edge-case, verification-gap lenses)

A sub-agent reviewed Story 11.1's code (`packages/macroable/**`, the Expectations shard, and #403's devDependency change) against Upstream `Illuminate\Support\Traits\Macroable` and `SupportMacroableTest.php`, with probes run in a `test` frame; no repository file changed. - **L1. A macro named like a JS built-in member is silently never called.** `install` (`Macroable.ts:80-85`) skips when `name in target`, which is true for inherited `Object.prototype` members (`toString`, `valueOf`, `hasOwnProperty`) and for a class's own or `Function.prototype` members (`name`, `length`, `call`, `apply`, `bind`). After `W.macro("toString", fn)`, `new W().toString()` returns `"[object Object]"`; after `W.macro("call", fn)`, `W.call()` throws `TypeError`. In PHP those names are no real method, so `__call` / `__callStatic` runs the macro. `docs/macroable.md:59` says "A macro never replaces a real method … as in PHP", and DIV-12.10 covers only names never registered. The Story's review rejected this as rare (spec, Review Triage Log); the retrospective does not accept it, because it is a silent divergence with no DIV clause and the docs present it as Laravel's behaviour. *Fix now* (action item 5).
  - *Status 2026-10-25: item 5 waits on the Maintainer.* The inherited-name half (`Object.prototype` / `Function.prototype` members such as `toString`, `call`) and L2 have a bounded fix within `packages/macroable`. The own-built-in half does not. Every class, and every subclass, has its own `prototype`, `name` and `length`, and every prototype has its own `constructor`. `prototype` cannot be redefined, and a dispatcher installed on the using class would still be shadowed by each subclass's own `name` / `length` / `constructor`, so no install makes these work as PHP's `__call` / `__callStatic` does. The item's options are to throw a clear error or wait on the Maintainer. Throwing where Laravel registers the macro is a new observable divergence: it needs a DIV-12 clause, which needs an Escalation (AGENTS.md stop rules; Epic 11 lesson "fix it, or record it under a DIV clause through an Escalation"). An action item has no Story to raise one from, so it waits on the Maintainer (`decisions/MAINT-2026-10-16-unattended-orchestrator.md`, amendment 2026-10-22, "Other questions"). **Question for the Maintainer:** may `macro`, and so `mixin`, throw for the names `prototype`, `name`, `length` and `constructor` under a new DIV-12 clause (recommended: the error names the reserved member and points to `__call` / `__callStatic`)? Or should it register such a macro so `hasMacro`, `__call` and `__callStatic` see it, with only the direct-call sugar missing, under that clause? Once ruled, the whole item is one `planning/retro-11-*` build. The inherited-name half and L2 are not landed separately, because the item's `action` covers all three and its Fidelity Review reads that scope.
  - *Status 2026-10-25, after the ruling: item 5 waits on the Maintainer again, for the host.* `decisions/MAINT-2026-10-25-epic-11-item-5.md` (DIV-12.11) settled the question above, and the build is done on `planning/retro-11-builtin-names` (loop 2, tree `8fa9e5e051fabe115e1f25d7a30c0a84d6146786`; reviewer 1 passed it on codex). The Fidelity Review cannot reach `current`: reviewer 2 runs on the loop's CLI, `claude`, and the host's `claude` CLI reports `Not logged in · Please run /login`. Choosing reviewers is the Maintainer's (MAINT-2026-10-16, amendment 2026-10-21), so the orchestrator does not move reviewer 2 to another CLI. **For the Maintainer:** sign the `claude` CLI in on the orchestrator host, then remove this id from `waiting_on_maintainer`; the orchestrator resumes at the review. Every Story's Fidelity Review needs the same CLI.
- **L2. `mixin` calls a mixin's static method with `this` the mixin instance.** `mixinMethods` collects the class's statics (`Macroable.ts:132-139`) and `mixin` runs every method as `Reflect.apply(method, mixin, [])` (`:174`). PHP's `ReflectionMethod::invoke($mixin)` on a static method has no `$this`, and `static::` is the class, so a static mixin factory that calls `this.otherStatic()` throws a `TypeError` in Xaravel. *Fix now* (action item 5).
