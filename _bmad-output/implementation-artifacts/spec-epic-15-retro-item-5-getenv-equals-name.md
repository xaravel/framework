## Intent

**Problem:** After `putenv("FOO=bar=baz")`, the runtime's `getenv("FOO=bar")` returns `false`, where PHP 8.5.11 on the Oracle image (`php:8.5.11-cli-trixie`, glibc) returns `"baz"` (finding L3, action item `epic-15-retro-item-5-getenv-equals-name`). The lookup `Object.hasOwn(process.env, key)` never matches a name holding `=`.

**Approach:** Make `getenv(name)` do what glibc's `getenv` does: return the text after `<name>=` in the first environment entry (`<entry name>=<value>`, in `process.env` order) that starts with `<name>=`, else `false`. The Oracle probe row is the one the monitor recorded in `decisions/MAINT-2026-10-30-epic-15-items-2-5.md` (Item 5); a new XT-runtime case asserts its four results and cites that file.

## Boundaries & Constraints

**Always:** scope `packages/runtime/**` and this item's records; the four Oracle results in the decision file are the expected values; a name with no `=` behaves exactly as now; `getenv()`/`getenv(null)`, `putenv`, `superglobals`, the TypeErrors and the NUL / lone-surrogate limits are unchanged; correct the docs and the probe comment that say glibc finds no entry.

**Never:** record this row from the host's macOS PHP (it gives `"bar=baz"` for all three `=` names: wrong libc); another component, PORTING.md, a DIV, the grader or Expectations; any other runtime behaviour change; a cache or module state.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| prefix with `=` | `putenv("FOO=bar=baz")`; `getenv("FOO=bar")` | `"baz"` | No error |
| partial value | same; `getenv("FOO=b")` | `false` | No error |
| plain name | same; `getenv("FOO")` | `"bar=baz"` | No error |
| whole entry | same; `getenv("FOO=bar=baz")` | `false` | No error |
| empty rest | `putenv("FOO=bar=")`; `getenv("FOO=bar")` | `""` (glibc returns the empty text after `FOO=bar=`) | No error |
| no entry | no name `FOO`; `getenv("FOO=bar")` | `false` | No error |

## Design Notes

glibc `getenv(name)`: for each `environ` entry, `strncmp(entry, name, len) == 0 && entry[len] == '='` → `entry + len + 1`. With `entry = name' + "=" + value`, a key holding `=` matches iff `` `${name'}=${value}` `` starts with `` `${key}=` ``. Order is `process.env`'s (ESC-15.2-2's source, already documented: only integer-like names move); first match wins.
