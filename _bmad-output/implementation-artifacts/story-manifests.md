# Story manifests

Sprint planning writes `stories/<story-id>.md` (AD-16). This note records the conventions it uses.

- **Story ID.** The Story number from `epics.md`, dotted: `1.1`, `14.3`. The branch is `story/<story-id>` and Escalations are `ESC-<story-id>-<n>` (for example `ESC-1.1-1`). Each manifest's `sprint_key` names its entry in `sprint-status.yaml`.
- **Status.** `sprint-status.yaml` is the authority for whether a Story is open. `ownership manifests` takes each manifest's effective status from `development_status[<sprint_key>]`, and fails a `sprint_key` that sprint status does not list. A Story's `development_status` value must be one of `backlog`, `ready-for-dev`, `in-progress`, `review`, `done` or `blocked`, and only `done` counts as closed. The manifest's own `status` is sprint planning's snapshot, used only when a root has no sprint status or a manifest has no `sprint_key`. Story PRs update sprint status, never `stories/*.md` (a Protected Path).
- **Xaravel Test IDs.** Each acceptance criterion (one `**Given**` block) gets one `XT-<component>-<n>`, numbered per Component in file order. A Story may add further Xaravel Tests for a criterion, but it must not renumber those already allocated.
- **Coverage so far.** Manifests exist for Phase 0 (Epics 1–8) and, since the 2026-10-17 refresh after Epic 2, for 217 of the 252 Phase 1–8 Stories (Epics 9–70). Phase 9 (Epics 71–74) is outline only and has none. The 35 deferred Stories below get their manifests when each is planned. Phase 0 must finish before Phase 1 starts, so no Story is waiting on them yet.
- **Selector resolution.** A Phase 1–8 manifest's `test_ids` are its Story's Upstream selectors, applied to the Test Inventory (`conformance/inventory/*.jsonl`) at the Baseline Pin. A selector matches a Test ID by file path (the inventory `source` path, or the path PSR-4 derives from the class) and by method name (the part of the ID after `::` and before any `#` data set). Brace groups and Epic abbreviations (`SCT`, `QBT`, `EMT`, …) are expanded first. All explicit selectors are applied in Story order, so a Test ID an earlier Story matched belongs to that Story. Then each residual rule (for example "every `SCT` Test ID that no selector matched") takes what is left in its file. Each manifest lists its selectors under its criteria table. The extracted scopes and the resolver are in `sprint-planning/` beside this file. Re-run the resolver when a deferred Story is planned or the Pin moves: `python3 -I sprint-planning/resolve.py <repo> sprint-planning [--write]`.
- **Exact names that are prefixes.** Some `epics.md` selectors name a method exactly that doesn't exist, for example `EMT::testForceFill`, where Upstream has `testForceFillMethodFillsGuardedAttributes`. When an exact name matches nothing, the resolver treats it as a prefix (`testForceFill*`). That happened for 38 selectors in Stories 34.4, 34.5, 36.1, 36.2, 36.4, 36.5, 36.6, 37.1 and 37.5, each widening to one or two Test IDs. Three selectors still match nothing: 37.5 `EBT::testWhereHas*`, 43.4 `VVT::testValidateExists*`, and the 60.9 residual on `tests/Integration/Database/DatabaseTestCase.php`, which is a base class.
- **Deferred Stories.** These have no manifest yet:
  - Their scope is Expectations entries, or a re-verification of Test IDs another Story owns. These are 19.3, 19.4, 28.3, 32.3, 33.3, 38.6, 40.2, 45.2, 46.2, 47.4, 50.3, 54.6, 56.4, 60.5, 62.6, 64.3, 65.1, 65.3, 66.5 and 70.3. AD-16 allows a Test ID in only one open Story, so a re-verification can list those IDs only once the owning Story is `done`.
  - Their scope needs one manifest per owning Component, which `stories/<story-id>.md` can't express. These are 33.4, 39.4, 43.7, 53.8, 55.4, 60.1, 60.2, 60.3 and 60.16.
  - `epics.md` names their scope by topic only, with no selector. These are 68.1, 68.2, 68.3 and 69.1.
  - Their scope includes Inventory Test IDs whose data-set name ends in a space. These are 43.6 (`ValidationRuleBuilderMethodTest::testConditionalRuleParameters{ArePreserved,CannotBypassValidation}`, 12 IDs) and 60.10 (`testWhereJsonContainsKey#integer key with arrow `, 6 IDs). The manifest validator (`tools/ownership`, Story 1.5) rejects a list entry with surrounding whitespace, so these IDs can't be listed until the validator or the Inventory's ID form changes.
- **Unowned Test IDs.** After resolution, 7,554 Inventory Test IDs belong to no manifest. They are the deferred Stories' scopes, the `laravel/ai` suites (Epic 72, outline only), the `mcp` and `boost` suites (68.x, 69.1), and Upstream files that no selector names.
- **Components.** Epics 1–3, 5, 6 and 8, and Stories 7.1–7.2, use `component: conformance`. Stories 4.1–4.4 use `assert`, 4.5–4.6 use `mockery`, and 7.3–7.4 use `boost`. Phase 1–8 manifests name the package their Epic ports, for example `collections` for Epic 14, `database` for Epics 34–39 and `testing` for Epic 57. Story 55.3 (generator reference files) uses `conformance`.
