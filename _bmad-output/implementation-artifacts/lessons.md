# Lessons

Durable, cross-epic process lessons from epic retrospectives. Every `bmad-build-auto` run loads this file as a persistent fact (`_bmad/custom/bmad-build-auto.toml`).

The orchestrator appends to it after each retrospective (`tools/orchestrator/iteration.md`, step C), one or two lines per lesson, each citing its retrospective document. It stays under 150 lines; older entries are consolidated, not dropped. The Maintainer may promote entries into `AGENTS.md`.

## Lessons

- (epic 1) A deferral must name the Story or Epic that takes it, and that target's ACs must actually cover it; check the chain when you defer. Epic 1 deferred CI gating from Stories 1.1, 1.3, 1.5 and 1.6 to Story 1.7, whose ACs never asked for it, so no CI job runs `bun test`, `tsc` or the graph check. (epic 3) It repeated: about 20 of 30 Epic 3 deferrals had no covering AC, and 3.3/3.4 deferred to a retro item the Maintainer had already closed. A gap with no target becomes an Escalation or an action item, never a spec row or status comment. Source: `_bmad-output/implementation-artifacts/epic-1-retro-2026-10-17.md`, `_bmad-output/implementation-artifacts/epic-3-retro-2026-10-18.md`
- (epic 1) Separate agent-run steps from Maintainer-run live steps in the spec up front: ruleset apply, token scopes, environments, merges. Three of eight Epic 1 Stories stopped on a permission the spec did not anticipate (1.2 merge, 1.4 `workflow` scope, 1.7 live ruleset apply). Source: `_bmad-output/implementation-artifacts/epic-1-retro-2026-10-17.md`
- (epic 1) The orchestrator runs as the Maintainer (org admin) and merges with `--admin`, so a check or ruleset that relies on identity separation is not verified by passing; report it as unverifiable, never as met. Source: `_bmad-output/implementation-artifacts/epic-1-retro-2026-10-17.md`
- (epic 1) When a Story is done, update both its sprint-status key and its `stories/<id>.md` manifest `status`; Epic 1 left every manifest at `backlog`, so the ownership check still counts finished Stories as open. (epic 5) It recurred for 5.7–5.10 after a one-off fix; a sync with no check does not hold. Source: `_bmad-output/implementation-artifacts/epic-1-retro-2026-10-17.md`, `_bmad-output/implementation-artifacts/epic-5-retro-2026-10-19.md`
- (epic 1) A contract between two Stories' tools (Escalation names vs manifests, write-scope allow-list vs release job, scaffolder references vs graph peers) has no owner in either Story's review; name the other side and test it from both ends. Source: `_bmad-output/implementation-artifacts/epic-1-retro-2026-10-17.md`
- (epic 1) A live check (`ruleset:verify`, release `gate`) must fail loudly with no credentials rather than report drift or pass; run it with the token set when you record it as verified. Source: `_bmad-output/implementation-artifacts/epic-1-retro-2026-10-17.md`
- (epic 1) Every orchestrator comment on the status issue starts with the robot-emoji prefix; Epic 1's first six lacked it, which makes them look like Maintainer comments to the checkpoint `go` scan. Source: `_bmad-output/implementation-artifacts/epic-1-retro-2026-10-17.md`
- (epic 2) Keep one source of truth for a pinned value and derive the rest from it; hash every build input into a cache or image key. Epic 2 copied the Pin into the Oracle Dockerfile and keyed the image tag on the locks only, so a Pin move breaks the build and a Dockerfile change reuses an old tag. Source: `_bmad-output/implementation-artifacts/epic-2-retro-2026-10-17.md`
- (epic 2) Code in another language that a tool runs (PHP listers, recorders) needs at least one test that actually executes it; fakes and string greps let a 21x assertion over-count reach committed data. The same applies to printed operator commands: test that they run, not that they match a string. Source: `_bmad-output/implementation-artifacts/epic-2-retro-2026-10-17.md`
- (epic 2) Before implementing, run the spec's own rules against its prototype data and check every format the Story needs is owned by a done Story; ESC-2.4-1 (rule vs count) and ESC-2.8-1 (Expectations formats owned by Epic 5) were both foreseeable. (epic 3) This includes heuristic rules you write into the intent contract yourself: 3.6 and 3.7 froze untested static-analysis rules, and each blocked only after a full build (23/202 null singleton classes; `assertCount` counted 0 of 1,741 sites). (epic 4) It includes the protected conformance tests: grep `conformance/tests/` for any package edge or path your design adds; 4.5 met XT-conformance-8's dependency rule only after a full build. (epic 5) It includes `escalations:check`, which accepts only Test IDs in the base-branch manifest: 5.3 and 5.7 each hit it after the build, and 5.7 cited a wrong on-manifest ID to pass. Source: `_bmad-output/implementation-artifacts/epic-2-retro-2026-10-17.md`, `_bmad-output/implementation-artifacts/epic-3-retro-2026-10-18.md`, `_bmad-output/implementation-artifacts/epic-4-retro-2026-10-18.md`, `_bmad-output/implementation-artifacts/epic-5-retro-2026-10-19.md`
- (epic 2) A spec note that something "needs a Maintainer ruling" must become an Escalation in `conformance/escalations/`, not a deferral row; nothing routes a deferral to the Maintainer. (epic 5) "Raise it at the retrospective" is the same gap (5.9, 5.10). Source: `_bmad-output/implementation-artifacts/epic-2-retro-2026-10-17.md`, `_bmad-output/implementation-artifacts/epic-5-retro-2026-10-19.md`
- (epic 2) Delete blocked-attempt patch files in the PR that applies them. (epic 10) The same for `bmad-build-auto-result-*` notes once their item is done; three older scratch files were still on `main` at the Epic 10 retro. Source: `_bmad-output/implementation-artifacts/epic-2-retro-2026-10-17.md`, `_bmad-output/implementation-artifacts/epic-10-retro-2026-10-24.md`
- (epic 3) "Fails the build" is not "blocks the merge": check whether the job is a required check before recording a guarantee as met. Epic 3's fixture-signature verification runs only in the advisory `check` job, so a forged fixture can merge green. Source: `_bmad-output/implementation-artifacts/epic-3-retro-2026-10-18.md`
- (epic 3) A workflow path that only runs live (`pull_request_target`, App commit-back) and is tested only by matching its YAML text is unverified; say so, and plan a supervised first run. When such a job runs Story-supplied code next to secrets, isolate its stdout, limit its container resources and keep the comments on who can read each secret accurate. (epic 5) A `pull_request_target` job that checks out and runs PR code needs the same-repository guard (`head.repo.full_name == github.repository`) on a public repo; `ratchet.yml` shipped without the guard `oracle.yml` has. Source: `_bmad-output/implementation-artifacts/epic-3-retro-2026-10-18.md`, `_bmad-output/implementation-artifacts/epic-5-retro-2026-10-19.md`
- (epic 4) A Story that ships beside its own open contract Escalation is not done on that point: record the AC as conditional on the ruling and report the Escalation as waiting on the Maintainer. `escalations:check` passes with no decision, so four Epic 4 contract Escalations merged unruled and nothing asked for a ruling. Source: `_bmad-output/implementation-artifacts/epic-4-retro-2026-10-18.md`
- (epic 4) When two packages need the same PHP semantics (value predicates, float formatting, `var_export`, object ids), export one implementation and reuse it; Mockery's copy of assert's helpers disagreed in four cases within a day. (epic 5) The same holds for Test ID selection: the harness and done check match exactly while ownership matches dataset rows. (epic 6) And for recognising a `registerClass` call: the registration scan normalises a leading `\`, the API-surface diff does not. (epic 7) When a workspace boundary forces a copy (Boost's mirror of the conformance buckets), guard it with an equivalence test and never document it as one source. (epic 9) Within the runtime too: `jsonEncode` re-implemented 9.6's type classification and diverged on integer-like keys, and Mockery's `getDebugType` missed the float marker the grader learned in the same epic; when a Story teaches one package a new protocol, grep every package that reads the same values. (epic 10) Epic 10 left four disagreeing "is this a contract token" predicates and a second thenable list the Story said it replaced. Source: `_bmad-output/implementation-artifacts/epic-4-retro-2026-10-18.md`, `_bmad-output/implementation-artifacts/epic-5-retro-2026-10-19.md`, `_bmad-output/implementation-artifacts/epic-6-retro-2026-10-19.md`, `_bmad-output/implementation-artifacts/epic-7-retro-2026-10-19.md`, `_bmad-output/implementation-artifacts/epic-9-retro-2026-10-22.md`, `_bmad-output/implementation-artifacts/epic-10-retro-2026-10-24.md`
- (epic 4) Never overwrite a tracked file, even temporarily, to run a local check (a subagent tried to swap `conformance/oracle/oracle.pub` for a throwaway key); run such checks in a copy outside the repo. Source: `_bmad-output/implementation-artifacts/epic-4-retro-2026-10-18.md`
- (epic 4) The Story branch is exactly `story/<story-id>` (`story/4.5`, not `story/4-5-mockery-core`); `oracle.yml` keys on it, and the wrong name failed #119. Source: `_bmad-output/implementation-artifacts/epic-4-retro-2026-10-18.md`
- (epic 5) When CI fails for a reason that applies to every job of a kind (a harness job needs `fetch-depth: 0`), fix every sibling job in the same PR; #160 and #164 each needed the same `[orchestrator fix]`. Source: `_bmad-output/implementation-artifacts/epic-5-retro-2026-10-19.md`
- (epic 6) A syntactic check that enforces an AD covers only the shapes its fixtures name. Before calling it done, probe the obvious evasions (a call result instead of `new X()`, an alias, a re-export, a nested call, a type alias) and every input source the underlying tool honours (oxlint skips `.gitignore`d files). Prefer a type-aware built-in rule where one exists, and list the remaining limits in the tool's docs. (epic 7) The same holds at runtime: framework mode's `Bun` denylist missed `Bun.fetch` (`file:` reads), `node:sqlite` and `Bun.Archive`; enumerate the whole API surface or use an allowlist. Source: `_bmad-output/implementation-artifacts/epic-6-retro-2026-10-19.md`, `_bmad-output/implementation-artifacts/epic-7-retro-2026-10-19.md`
- (epic 6) A check proven only on fixtures because the code it guards does not exist yet (registration scan, API-surface mappings) needs a named re-check when the first real code lands; otherwise "ok (0 registrations)" reads as verified. Source: `_bmad-output/implementation-artifacts/epic-6-retro-2026-10-19.md`
- (epic 7) Assert per case, not in aggregate: XT-boost-6's `0 < errors < calls` passes with a tool that always fails. Compile user-supplied patterns (globs) with a linear matcher or a length cap; `*` to `[\s\S]*` backtracks exponentially. Source: `_bmad-output/implementation-artifacts/epic-7-retro-2026-10-19.md`
- (epic 8) A gate that checks a document's headings, or a test whose expected values are copied from the data it checks, passes vacuously: `porting:check` passed with five required sections emptied, and `divergence.test.ts` hard-coded the DIV `cites` instead of reading the spine's `Binds:` lines. Check content, and derive expectations from the source contract. Source: `_bmad-output/implementation-artifacts/epic-8-retro-2026-10-20.md`
- (epic 8) When a ruling redefines how a tool works, update every file the tool reads or that describes it (Protected instructions, ops docs) in the same PR; `fidelity-review.ts` was rebuilt three times while `conformance/review/fidelity.md`, its reviewers' prompt, still describes the retired GitHub-App process. Source: `_bmad-output/implementation-artifacts/epic-8-retro-2026-10-20.md`
- (epic 8) Implement a ruling's scope exactly; a wider one needs its own recorded reason. ESC-8.8-1 excluded `stories/` status edits, sprint status and the spec's verdict records from the review binding, and the code excluded all of `_bmad-output/` and `stories/`, which lets a `test_ids` edit keep stale approvals. Source: `_bmad-output/implementation-artifacts/epic-8-retro-2026-10-20.md`
- (epic 9) When a reviewer or gate rejects for missing evidence, widen the general mechanism, not the one case: 12 of Epic 9's 23 Escalations were Fidelity Review evidence gaps or the prompt cap, each patched one slice at a time until the Maintainer ruled whole files (`decisions/MAINT-2026-10-22-fidelity-whole-files.md`). (epic 10) It recurred at 6 of 22, again over 12 one-case commits, until `decisions/MAINT-2026-10-24-evidence-gaps.md` made a missing-evidence-only reject non-blocking. Source: `_bmad-output/implementation-artifacts/epic-9-retro-2026-10-22.md`, `_bmad-output/implementation-artifacts/epic-10-retro-2026-10-24.md`
- (epic 9) Before setting an epic `done`, check every AC of its last Story, including ones a planning change must do "when the Epic closes"; Epic 9 was marked done while Story 9.12's DIV-9.8 closure had not landed. (epic 10) When only the Maintainer can complete such an AC (Story 10.6 needs `decisions/PHASE-1-EXIT.md`), record it as waiting on the Maintainer in the Story PR, not just in the spec. Source: `_bmad-output/implementation-artifacts/epic-9-retro-2026-10-22.md`, `_bmad-output/implementation-artifacts/epic-10-retro-2026-10-24.md`
- (epic 9) Test per-frame state with two concurrent frames, not one frame at a time, and check every side effect that escapes the frame: a brand written onto a shared class object, or a helper that opens a root frame, leaked or lost test registrations while each frame's own tests passed. Source: `_bmad-output/implementation-artifacts/epic-9-retro-2026-10-22.md`
- (epic 10) When a Story adds a new kind of framework value (a contract token), decide and test how every value path treats it: string conversion, the runtime encoders and exporter, and assert's display. Contract tokens throw on interpolation and read as PHP arrays, where PHP's `X::class` is a string. Source: `_bmad-output/implementation-artifacts/epic-10-retro-2026-10-24.md`
