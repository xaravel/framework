# Lessons

Durable, cross-epic process lessons from epic retrospectives. Every `bmad-build-auto` run loads this file as a persistent fact (`_bmad/custom/bmad-build-auto.toml`).

The orchestrator appends to it after each retrospective (`tools/orchestrator/iteration.md`, step C), one or two lines per lesson, each citing its retrospective document. It stays under 150 lines; older entries are consolidated, not dropped. The Maintainer may promote entries into `AGENTS.md`.

## Lessons

- (epic 1) A deferral must name the Story or Epic that takes it, and that target's ACs must actually cover it; check the chain when you defer. Epic 1 deferred CI gating from Stories 1.1, 1.3, 1.5 and 1.6 to Story 1.7, whose ACs never asked for it, so no CI job runs `bun test`, `tsc` or the graph check. (epic 3) It repeated: about 20 of 30 Epic 3 deferrals had no covering AC, and 3.3/3.4 deferred to a retro item the Maintainer had already closed. A gap with no target becomes an Escalation or an action item, never a spec row or status comment. Source: `_bmad-output/implementation-artifacts/epic-1-retro-2026-10-17.md`, `_bmad-output/implementation-artifacts/epic-3-retro-2026-10-18.md`
- (epic 1) Separate agent-run steps from Maintainer-run live steps in the spec up front: ruleset apply, token scopes, environments, merges. Three of eight Epic 1 Stories stopped on a permission the spec did not anticipate (1.2 merge, 1.4 `workflow` scope, 1.7 live ruleset apply). Source: `_bmad-output/implementation-artifacts/epic-1-retro-2026-10-17.md`
- (epic 1) The orchestrator runs as the Maintainer (org admin) and merges with `--admin`, so a check or ruleset that relies on identity separation is not verified by passing; report it as unverifiable, never as met. Source: `_bmad-output/implementation-artifacts/epic-1-retro-2026-10-17.md`
- (epic 1) When a Story is done, update both its sprint-status key and its `stories/<id>.md` manifest `status`; Epic 1 left every manifest at `backlog`, so the ownership check still counts finished Stories as open. Source: `_bmad-output/implementation-artifacts/epic-1-retro-2026-10-17.md`
- (epic 1) A contract between two Stories' tools (Escalation names vs manifests, write-scope allow-list vs release job, scaffolder references vs graph peers) has no owner in either Story's review; name the other side and test it from both ends. Source: `_bmad-output/implementation-artifacts/epic-1-retro-2026-10-17.md`
- (epic 1) A live check (`ruleset:verify`, release `gate`) must fail loudly with no credentials rather than report drift or pass; run it with the token set when you record it as verified. Source: `_bmad-output/implementation-artifacts/epic-1-retro-2026-10-17.md`
- (epic 1) Every orchestrator comment on the status issue starts with the robot-emoji prefix; Epic 1's first six lacked it, which makes them look like Maintainer comments to the checkpoint `go` scan. Source: `_bmad-output/implementation-artifacts/epic-1-retro-2026-10-17.md`
- (epic 2) Keep one source of truth for a pinned value and derive the rest from it; hash every build input into a cache or image key. Epic 2 copied the Pin into the Oracle Dockerfile and keyed the image tag on the locks only, so a Pin move breaks the build and a Dockerfile change reuses an old tag. Source: `_bmad-output/implementation-artifacts/epic-2-retro-2026-10-17.md`
- (epic 2) Code in another language that a tool runs (PHP listers, recorders) needs at least one test that actually executes it; fakes and string greps let a 21x assertion over-count reach committed data. The same applies to printed operator commands: test that they run, not that they match a string. Source: `_bmad-output/implementation-artifacts/epic-2-retro-2026-10-17.md`
- (epic 2) Before implementing, run the spec's own rules against its prototype data and check every format the Story needs is owned by a done Story; ESC-2.4-1 (rule vs count) and ESC-2.8-1 (Expectations formats owned by Epic 5) were both foreseeable. (epic 3) This includes heuristic rules you write into the intent contract yourself: 3.6 and 3.7 froze untested static-analysis rules, and each blocked only after a full build (23/202 null singleton classes; `assertCount` counted 0 of 1,741 sites). Source: `_bmad-output/implementation-artifacts/epic-2-retro-2026-10-17.md`, `_bmad-output/implementation-artifacts/epic-3-retro-2026-10-18.md`
- (epic 2) A spec note that something "needs a Maintainer ruling" must become an Escalation in `conformance/escalations/`, not a deferral row; nothing routes a deferral to the Maintainer. Source: `_bmad-output/implementation-artifacts/epic-2-retro-2026-10-17.md`
- (epic 2) Delete blocked-attempt patch files in the PR that applies them. Source: `_bmad-output/implementation-artifacts/epic-2-retro-2026-10-17.md`
- (epic 3) "Fails the build" is not "blocks the merge": check whether the job is a required check before recording a guarantee as met. Epic 3's fixture-signature verification runs only in the advisory `check` job, so a forged fixture can merge green. Source: `_bmad-output/implementation-artifacts/epic-3-retro-2026-10-18.md`
- (epic 3) A workflow path that only runs live (`pull_request_target`, App commit-back) and is tested only by matching its YAML text is unverified; say so, and plan a supervised first run. When such a job runs Story-supplied code next to secrets, isolate its stdout, limit its container resources and keep the comments on who can read each secret accurate. Source: `_bmad-output/implementation-artifacts/epic-3-retro-2026-10-18.md`
