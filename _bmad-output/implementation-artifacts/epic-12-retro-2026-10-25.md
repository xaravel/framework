### Diff-scope review (adversarial, edge-case, verification-gap lenses)

A sub-agent reviewed #427 and #428 against Upstream `Illuminate\Support\Traits\Conditionable` and `HigherOrderWhenProxy`, as the second pass of the Blind, Edge and Verification-gap layers the spec asked for (`followup_review_recommended: true`, Auto Run Result). No repository file changed. L1 and L2 were re-checked by the orchestrator against `Conditionable.ts`. Checked and sound: the closure `value` is called with `this` before the argument count is read; `?? this` on both the callback and the default branch; `when()` returns a plain proxy and `unless()` a `negateConditionOnCapture()` one; `unless(v)` sets `condition(!v)`; a `null` callback on a truthy value throws `Value of type null is not callable`; `registerClass` ends each class file; no `undefined` leaks; the Ported assertions are Upstream's one-for-one.

- **L1. With an async callback, whether `when` / `unless` return a Promise depends on the condition.** `conditional` (`Conditionable.ts:144-150`) returns `invoke(callbackFn, …) ?? self` on the taken branch and `self` otherwise, so `when(false, async () => …)` returns `this` synchronously, and on a thenable target (a query Builder) `await b.when(cond, async …)` runs the query only when `cond` is false. The spine's dual-helper rule (`ARCHITECTURE-SPINE.md:179`) says "`Promise<T>` for an async one". And because a Promise is never `null`, `await x.when(true, async () => null)` gives `null` where Laravel's `?? $this` gives the target; XT-conditionable-2 asserts that `null` (`conditionable.test.ts:349`). Both follow from the Maintainer's re-plan ruling (callbacks' own types, the Promise "returned as is"; `decisions/MAINT-2026-10-25-story-12-1-replan.md`, Question 1), and neither is recorded in DIV-1.6. Changing either is a divergence or typing question. *Fix now* through the Maintainer (action item 3).
- **L2. An invokable object is rejected as a callback.** `callableArgument` (`Conditionable.ts:91-92`) throws `must be of type ?callable, <class> given` for every non-function. PHP's `?callable` accepts an object with `__invoke`, and the repo already treats one as callable (`packages/macroable/src/Traits/Macroable.ts:229`). No DIV clause covers it, and the fix needs none: accept the object and call its `__invoke`. *Fix now* (action item 1).
- **L3. PHP callable strings and arrays are rejected** (`Conditionable.ts:94-96`): `'strtoupper'` and `[$obj, 'm']` throw `TypeError` where Upstream accepts them. The spec lists it as a residual risk and the docs record it, but no DIV clause does. Per LESSONS (epic 11), a divergence is fixed or recorded under a DIV clause through an Escalation; an action item cannot raise one. *Fix now* through the Maintainer (action item 3).
- **L4. The proxy generates members only for the target's real methods** (`HigherOrderWhenProxy.ts:208-245`, DIV-12.12). Methods a target serves through its own `__call`, as Eloquent's `Builder` does for most query methods, are not reachable by name, so Laravel's `query()->when(true)->orderBy(…)` would be `undefined is not a function` unless `Builder` declares `orderBy` as a real member. Nothing exercises it yet (S1). *Defer* to the Database Builder Story, named in action item 4.
- **L5. XT-conformance-82's citation loop skips a bare `DIV-<n>`** (`conformance/tests/xaravel/api-surface.test.ts`): a citation not matching `^DIV-(\d+)\.(\d+)$` has `clause === null`, so only `checkCitations` covers it. *Accept*: `checkCitations` rejects an unknown record.
- **L6. The blocked `ConditionableTest` bodies reach `TestConditionableModel` and `Builder` through `resolveClass`** (`ConditionableTest.test.ts:17-24`) with `adapted: null`. Harmless while skipped; the header says unblocking declares the local class. *Accept*, carried by action item 4.
