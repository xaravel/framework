### Spec-to-implementation reconciliation

Every AC has code and an `XT-conformance-<n>` test that compares exact per-file diagnostics over failing and passing fixtures, so removing a rule fails its test: 6.1 (XT-129..131, XT-254), 6.2 (XT-132), 6.3 (XT-133, XT-249), 6.4 (XT-134 and the `async-surface.test.ts` set), 6.5 (`api-surface-diff.test.ts`, XT-198 for the `get_declared_classes()` cross-check), 6.6 (`registration.test.ts`, XT-254). Every gating tool runs in the required `check` job of `ci.yml` on `pull_request` and `merge_group`: `lint` (oxlint with the `xaravel` plugin, then `lint:disables`), `async-surface --all --check` (`ci.yml:133-134`) and `registration:check`. Every new tool file sits under the `/tools/` Protected Path; `.oxlintrc.json` is listed explicitly.

- **S1. 6.4 requires an `@asyncRoot` tag on sync methods that return a thenable.** `isPromiseType` treats any return type whose short name is in the thenable list as async (`tools/async-surface/async-surface.ts:128-136`), and the spec's own fixture tags `where(): Builder` with `@asyncRoot callback` (`spec-6-4:48`). AD-6 says "every async public method carries a docblock tag" (spine:188), and a builder method such as `DB.table(): Builder` or `Http.withHeaders(): PendingRequest` is not async; Fidelity Review would then check a false tag. Matching by short name also catches `Schema\Builder` as if it were `Query\Builder` (probe: `Connection.getSchemaBuilder(): Builder` fails). The AC wording "Promise- or thenable-returning" encodes this, so it is a contract question. *Fix now* through the Maintainer (action item 7).
- **S2. 6.5 applies the DIV-12 renames only partly.** `model-config` pairs only suppress the Upstream member, and the PRD's fixed rename (`fillable` → `setFillable`, `touches` → `isTouching`, PRD:1272) is not mapped, so each port surfaces as an `extra` needing a hand-written addition; `option-pair` marks both forms not expected, so a port that drops both is invisible (`tools/api-surface/api-surface.ts:956-981`). The AD-26 options object is accepted as an alternative to the positional form rather than in addition to it: `bestFailures` returns `[]` as soon as any signature passes (`:875-915`), so a Component can pass the gate without the overload AD-26 requires. *Defer* to before the first Component gate (action item 9).
- **S3. 6.5 "posts a per-Component summary" is met as a job summary, not a PR comment** (`.github/workflows/api-surface.yml:12-13,43-54`), a deliberate AD-16 choice that avoids fork-PR token problems. A single tool failure (one package's tsc error) drops the whole table (`api-surface.ts:1265-1271`). *Accept*.
- **S4. Nothing runs `api-surface:gate`.** It appears only in a comment (`api-surface.yml:9`); `tools/story-check`, `tools/orchestrator` and every workflow omit it, while Component-close ACs say "`api-surface:gate <c>` passes" (e.g. `epics.md:3376`, `:3903`). Such an AC would be accepted on the agent's word. *Fix now* through the Maintainer before Epic 10 closes (action item 8).
- **S5. 6.1's lint coverage of compiled-view snapshots is a placeholder.** `IGNORE_PROBES` in `disables.ts` and the XT-129 placement assume `.ts` files under `packages/view/tests/__snapshots__/` (`spec-6-1:148,197`), but Bun writes `.snap` files that oxlint does not lint, and Story 49.1's ACs do not ask for lint over compiled views. *Defer* (action item 9).
- **S6. 6.3's "false boot-only entries are gone" is checked only when the Upstream snapshot is synced.** Without it, `scanCheck` in XT-133 and XT-249 prints a warning and returns, as in the `check` job and locally; the `upstream` job enforces it (`ci.yml:165,173`). The regeneration dropped 21 entries, not only the two the AC names (including `*Manager::$customCreators`); the drops are documented in `docs/ops/scans.md` and flagged in `spec-6-3` for Maintainer review. *Accept*, with the drops recorded here for the Maintainer.

### Diff-scope review (adversarial, edge-case, verification-gap lenses)

Three sub-agents reviewed 6.1–6.3, 6.4–6.5 and 6.6 plus the cross-story wiring, with evasion probes under `/tmp`. Checked and sound: type information reaches the real tree (a probe config produced type-aware diagnostics in `packages/assert` and `packages/mockery`); `lint:disables` tokenizes comments, skips strings and regexes, and covers `extends`, `overrides`, nested configs, `ignorePatterns`, `.eslintignore` and JS configs; the `get_declared_classes()` cross-check (`tools/oracle/api-surface.php:279-311,385-391`) passes at the Pin for framework, ai, boost and mcp; the async-surface drift check prints `-`/`+` diffs; `api-surface:gate` exits 1 on any unexplained member; duplicate FQCNs are compared ignoring case and a leading `\`.

- **L1. `xaravel/no-async-thenable-return` misses a builder returned from a call.** `returnedThenable` recognises only `new X()`, `expr as X` and a local declared as a thenable (`tools/lint-rules/plugin.ts:942-961`). `async find() { return this.query(); }`, where `query()` returns a `Builder`, passes lint, also when annotated `Promise<readonly string[]>`; the Promise resolves to the builder's terminal result. Spine:183 makes this a lint error. The custom plugin has no type information; the type-aware built-in `typescript/return-await: ["error","always"]` reports both probe lines but is broader than the spine bullet. *Fix now* through the Maintainer (action item 6).
- **L2. A `.gitignore` entry removes a tracked file from lint and `lint:disables` still reports ok.** oxlint honours `.gitignore`; `disables.ts` checks `ignorePatterns` and `.eslintignore` (`:32`, `:490`) but not `.gitignore`. Probe: a force-added, gitignored `packages/demo/src/Bad.ts` with `x.constructor.name` was skipped and `lint:disables` printed `ok`. The root `.gitignore` has unanchored `dist/`, `build/` and `coverage/` (lines 3-5), so any `packages/*/src/**/build/` directory goes unlinted. *Fix now* (action item 3).
- **L3. `no-ported-bun-expect` can be bypassed by a re-export.** It inspects only imports in files under `tests/ported/` (`plugin.ts:346-392`). A helper `packages/demo/tests/support/e.ts` with `export { expect } from "bun:test"`, imported by a Ported Test, gives no diagnostic (probed). A `/// <reference types="bun-types/test-globals" />` global `expect` is a second route (not run). *Fix now* (action item 4).
- **L4. `no-singleton-field-write` sees only direct `this.f = …`.** `this.routes.set(k, v)`, `this.stack.push(x)`, `this.cache[k] = v`, `Object.assign(this, …)` and `const self = this; self.current = …` pass in a registered `Router` (`plugin.ts:1046-1071`; `MUTATORS` at `:1015` is used only by `no-boot-only-write`; the exclusion is documented at `lint-signatures.test.ts:267-271`). Laravel's managers legitimately cache drivers at runtime, so widening it needs a ruling. *Defer* (action item 9).
- **L5. `singletons.json` `classes` omits singletons built in closures** (`class: null` for `view`, `session.store`, `cache.store`, `queue.connection` and others; residual from `spec-3-6:334`), so `Illuminate\View\Factory`, the main holder of per-request state, is never checked. *Defer* (action item 9).
- **L6. `no-maybe-promise-return` is syntactic** (`plugin.ts:766-777`): `type MaybePromise<T> = T | Promise<T>` and an unannotated method returning `1` on one path and `Promise.resolve(2)` on another pass. The same holds for 6.4's documented limits (a Promise type alias, a const typed by an object literal, an inherited method from a non-exported base, a namespace member, an exported `let`; `async-surface.ts:127-148`, `:266-337`, `docs/ops/async-surface.md:79,83`). *Defer*; the lesson is in LESSONS.
- **L7. Aliasing dodges the identity and JSON rules:** `const C = x.constructor; C.name`, destructuring, `Reflect.get(…)` and `const J = JSON; J.stringify(v)` pass (`plugin.ts:290-342`). ESC-6.2-1 acknowledges it. `no-dynamic-column-default` checks only classes extending `Model`, `Pivot`, `MorphPivot` or `Authenticatable` by that name (`plugin.ts:1247-1258`), so `class Admin extends User` passes. *Accept*; review catches these.
- **A1. 6.5 registers any `Symbol.for('<string>')` inside a top-level `const` initializer as a contract FQCN** (`api-surface.ts:409-432`, `:492`). Probe: `const SLOT = { key: Symbol.for("xaravel.cache.slot") }` produced `extra class xaravel.cache.slot`. The spine's own brands (`xaravel.php.array`, `xaravel.scope.run`) will then need `additions.jsonl` lines, which accept only FR or DIV citations. *Fix now* (action item 2).
- **A2. The gate does not validate citations.** It only checks `citation` is a string (`api-surface.ts:1213-1222`); an exceptions line with `citation: ""` explains a missing member, printed as `(explained: )`. Citation validation (`tools/oracle/api-surface.ts:303`) runs only in the path-filtered, non-required `oracle.yml`. A line with a mistyped `component` is ignored and never reported as stale (`:926-927`). *Fix now* (action item 2).
- **R1. Some `registerClass` calls are invisible to the duplicate check.** `registerCall` inspects only top-level `ExpressionStatement`s (`tools/registration/registration.ts:121-132`, `:220-232`), so `if (…) { registerClass(…) }`, `void registerClass(…)` or a parenthesised call is neither counted nor flagged, and a duplicate FQCN passes CI. *Fix now* (action item 1).
- **R2. Some exported classes escape the "ends with `registerClass`" rule:** `exportedClasses` sees only `ClassDeclaration` (`registration.ts:154-206`), so `export const Foo = class {}`, `export = Foo` and a namespace class pass, and `docs/ops/registration.md` § Limits lists none of them. *Fix now* (action item 1).
- **R3. One class may be registered under two FQCNs, and a file may register a class it imports** (`registration.ts:233-245`, `:337-351`), which makes `fqcn(Foo)` ambiguous and sidesteps AD-22's one owner. *Defer* to Story 9.4's Registry (action item 9).
- **R4. Two parsers decide what a registration is.** The scan normalises a leading `\` and case (`registration.ts:122-145`); api-surface keys the literal as written (`api-surface.ts:499-514`), so `registerClass('\\Illuminate\\X\\Foo', Foo)` passes the scan but mismatches Upstream in the diff. *Fix now* together with R1 (action item 1). Lesson: one recogniser, shared.
- **R5. The grader list exists three times:** `GRADER_PACKAGES` (`plugin.ts:117`), `GRADER_LOCATIONS` hard-coding `(assert|mockery)` (`plugin.ts:148`), and `kind: "grader"` in `tools/scaffold/packages.jsonl`; `registration.test.ts:162` compares only the first with the table. *Fix now* (action item 5).
- **R6. Scaffold packages outside `packages/` are never scanned** (`registration.ts:87-89`): `installer/` (published) and `tools/boost-framework`. A `sideEffects` of the string `"false"` or an object passes. *Defer*.
- **Verification gap V1.** Every Component package is still a scaffold: `registration:check` finds 0 registrations, and all 41 api-surface components report 0 matched, 0 extra. The FQCN regex, the duplicate key, and the camelCase, AD-26, DIV-12, default and nullability mappings have run only on fixtures. Re-check them when the first real ports land (action item 9).
